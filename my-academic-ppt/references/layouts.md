# 布局与视觉语法

## 先提炼参考，再选择版型

有参考 PPT 时，查看实际页面而不只提取文字：标题/正文比例、模块尺寸、图文比例、边框、箭头、底部结论、留白与颜色各是什么作用。沿用这些可观察的关系，不复制私人图件或把某一主题的章节结构当通用规则。

无参考时，以浅色背景、深蓝或相近的低饱和主色、深色正文、少量暗红等强调色作为起点。配色与字体服从用户模板。先按 [完整页面参考库](gallery.md) 的索引选择与当前信息关系相近的2–4张图，查看可编辑PPT及对应的全尺寸导出图；无视觉能力时读逐页布局JSON。37张示例包含科学图、解释文字和证据关系；它们示范组织方法，合成内容不能用作研究结果。

参考稿页数较多时，先通览全稿联系表，再逐页看实际画面，把不同布局及其变体列为覆盖清单；复杂页另作放大。页数很多或工具受限时记录未查看范围，继续查看与当前任务相关的页面。不要只挑最整齐的分栏页，漏掉不对称主图、多层证据、跨区汇聚、正式表格和平台界面。

## 页面选择

下列是可混合、可变形的构图起点，不限制新布局。先判断内容属于过程、比较、组成、尺度变化还是单一关键证据，再选择适合的空间关系；不要先选模板再切碎研究内容。

| 任务 | 适用构图 | 每块放什么 | 需要表达的关系 |
|---|---|---|---|
| 概括章节 | 左侧主标题，右侧简洁竖向路线 | 对象/方法/检验等真实步骤 | 本章如何推进问题 |
| 比较方法或证据 | 2–4栏图文模块 | 小标题＋解释图＋关键文字＋短结论 | 并列比较或互补 |
| 说明技术路线 | 流程为主，节点内有小图，节点旁有条件/产出 | 输入、关键操作、筛选依据、输出 | 串行、并行汇合、反馈 |
| 讲一个结果 | 大证据图＋2–3块解释或补充证据 | 怎么读、观察到什么、意味着什么 | 主证据与支撑 |
| 讲系统组成 | 矩阵、分层或两组互补模块 | 资源、方法、任务、可测产出 | 组成、接口、约束 |
| 总结 | 少量综合模块＋醒目总判断 | 主要发现、意义、下一步 | 归纳，而非新增分支 |
| 原理与验证 | 上下两层，上层机制，下层实验/工程验证 | 原理图、可测指标、验证步骤 | 机制怎样被检验 |
| 问题与解法映射 | 多层逻辑梯级或对应矩阵 | 挑战、方法、评价标准、目标 | 每个方法回应哪个问题 |
| 不等量证据 | 不对称拼版，例如左侧两个小单元、右侧一张主图 | 主证据、补充观察或对照 | 面积随证据权重分配 |
| 整体与局部 | 主图＋局部放大窗，必要时多层放大 | 全貌、关键区域、尺度或位置标记 | 局部位于哪里、解释什么 |
| 方法连接多结果 | 侧边流程＋结果图阵 | 步骤和相应证据面板 | 方法与结果逐项对应 |
| 跨尺度或多约束 | 大小不同的图版或共享轴的对照图阵 | 尺度、条件、约束及统一指标 | 在什么条件下可比 |
| 平台与记录 | 场景与标注主图、文档证据与相邻判断、功能目录 | 真实对象图、功能标记、证据定位 | 能力如何使用、判断依据在哪里 |
| 实施与验收 | 正式矩阵、评价表或风险响应表 | 任务、条件、可核验输出、判据 | 任务怎样落地与检查 |
| 时间或阶段推进 | 横向阶段、时间线或带关键节点的演化图 | 阶段、转折、证据与产出 | 时间/因果关系按实际区分 |

这些组合可交叉使用：例如上层呈现整体机制，下层用不对称证据组说明验证；不需要在有限的候选版型中二选一。

不是每页都分栏。选择能表达科学关系的版型，跨页保持统一视觉语言；同一版型中的模块共用网格和基线。

## 模块要有内容，也要有呼吸

一个常用模块包含标题条、图像区、必要说明和底部短结论。细虚线框可把图片和正文收拢在一起，避免边框层层嵌套。图片应说明对象、过程或证据；没有合适图片时，用有信息的原生示意图、紧凑表格或对照关系，不硬塞装饰小图。

横向图像区用合理裁剪、组合或经科学判断可旋转的图形填好有效宽度。保留比例，避免图缩成中央小点，也不拉伸结构图。旋转坐标图、医学方向图或改变方向会改义的图时优先重新构图。

多面板数据图本身足以承载论证时可以占大部分页面；增加必要的结论和读图顺序即可，不强行再做卡片。

## 字体与尺寸

同一语言选一套实际可用、可嵌入或目标系统可替代的无衬线字体，数字与英文风格协调。加粗和大小承担层级，不靠混用多种字体。

以13.33×7.5英寸宽屏为例，以下为**实际 PowerPoint pt**的起点，须按最终显示调整：

| 元素 | 起点 |
|---|---|
| 普通页标题 | 28–34 pt |
| 章节大标题 | 36–46 pt |
| 模块标题 | 20–24 pt |
| 正文、主要图标注 | 18–22 pt |
| 全页关键结论 | 22–26 pt，至少不弱于正文 |
| 辅助标签/必要引用 | 14–16 pt，关键实验信息不能靠这一层承载 |

生成库的逻辑像素、SVG像素和PPT的pt不是同一单位；先查当前工具的单位并试渲染，不直接复制这些数值。边距约为画布宽的4%–6%、模块间距约为1.5%–3%可作为起点。

放不下时先精炼句子、改变分组或拆页。不要把字号一路缩小来维持固定页数。

## 对齐和关系图形

- 叙述性正文通常左对齐；栏底短结论与模块中心对齐；数据表按比较方向对齐。不是所有文字居中。
- 主要流程箭头使用远距离可见的实心箭身，次要引线和精细结构标注可采用较细线条。主箭头的宽度与模块大小匹配。箭头占据两端可见图形或文字之间的中点，留出间隙；不能仅对齐文本框而贴住字。
- 只有真实先后关系才串联。并行方法各自汇入筛选，反馈从检验返回待更新的步骤；返回箭头写清回传的信息。
- 加号表示合并贡献，括号覆盖所有被汇总的模块，不能只框住其中一组。环形流程和回路箭头仅在循环关系真实存在时使用，中央大圆不是表达“相互关联”的默认方式。
- 简图也应交代对象、操作和输出。只有“输入→处理→结果”且没有科学内容的方框不能充当技术路线。

## 视觉检验

先做一次“删元素”检查：框线是否有助分组，箭头是否表达关系，标题下是否还需要副标题，底部结论是否与标题重复。能省而不损失理解的元素就省；复杂内容则允许增加新的空间组织方式。

缩略图检查阅读路径与整稿节奏；单页正常显示检查图文是否可读；放大检查裁剪和细节。章节标题应能与右侧流程抗衡，状态信息位于概括语下方等次要区域。若设置全页结论，它应醒目；标题已清楚表达结论时，可以不再重复底部句子。长句先精炼，再调整空间。避免明亮糖果色、拟物光泽、过度圆角和无含义装饰带来的玩具感。
