# 实现与验收

## 首选制作工作流

这是一套已用于科研汇报制作与局部修订的首选路径。先检测现有环境和适用工具说明，沿用已认可的源文件；工具本身不能代替设计、内容和实际画面验收。

**制作与渲染前先确认字体。** 在合法可用的本地字体目录中查找所需字体；必要时给绘图/渲染运行时注册字体文件，不在可复用代码里写死个人路径。读取已安装PowerPoint资源中的字体文件不需要启动PowerPoint，也不代表已经在PowerPoint中验收。注册后仍检查实际输出是否遵循中西文默认字体规则。

1. **JavaScript 制作可编辑PPT。** 环境提供 `@oai/artifact-tool` 时优先使用其演示接口放置文字、获准图片、原生形状、箭头、表格和图表，导出 `.pptx`。沿用统一组件与坐标，图片按素材指南获取，不能把整页绘成图片后冒充原生对象。先用代表页确认当前版本接口、文字单位和导出行为，再批量生成。
2. **Python 辅助与局部修订。** 用Python提取用户文件中的图片、整理数据、核对数字和备注，以及在适合时修改PPT包内的目标对象。保留现有用户手工改动；不要为了小改动从旧脚本重建整稿。替换整页时同步处理媒体、图表、工作簿、备注及其引用关系，不能只覆盖 `slideN.xml`。核对非目标页的文本、对象、关系和实际画面；能保留包内部件原样时比较前后哈希，重写工具会改变XML时检查内容与渲染等价。
3. **重新读取最终PPT并渲染。** 从实际待交付的 `.pptx` 重新导入后逐页渲染，不只渲染导出前的内存对象。可使用 artifact-tool 的导入/渲染接口；有适用环境时，再用PowerPoint或LibreOffice检查目标文件的字体、图表和版式。记录实际使用的渲染器，修正后重导出并复查。
4. **形成可查看的预览。** 可用ReportLab按原始宽高比把已核对的页面图片合成预览PDF，也可直接由演示软件导出PDF。ReportLab在这里仅负责组合图片，不负责渲染PPT，所得PDF不是另一套独立的PPT排版验证。PDF页码及内容必须对应同一份最终PPT。

## 能力缺失时的替代

优先复用现有运行时、依赖发现入口和可用的文档会话。其他Agent没有 artifact-tool 时，可用实际可用的PowerPoint、LibreOffice、PptxGenJS、python-pptx或其他演示接口；遵循该环境的工具约束，并保留可编辑对象、用户手改和同等验收要求。首选流程不授权自动安装软件、分发字体或外传材料。已有稿只需局部修改时，以最小且可验证的编辑路径为先，不因首选工具名称而强制迁移整稿。

写入与渲染分别验证：生成库能写PPTX不代表能正确渲染。缺少渲染能力时保留成品与实际已完成的检查，说明未验证范围；不把逐页图片、HTML或仅由图片合成的PDF称为已完成的可编辑PPT，也不声称未运行的软件已经通过测试。

字体按 [布局指南](layouts.md) 的中文微软雅黑、英文及数字 Times New Roman 设置，不预设本机安装路径。检查字体可用性、混排槽位和实际渲染；替代规则也以该指南为准，不能由生成库或系统默认字体悄悄覆盖。

## 制作方式

建立少量可复用组件：标题、章节入口、图文模块、粗箭头、重点结论、页码。用统一坐标、颜色和字号控制全稿，局部内容驱动组件大小，避免为每页另造视觉系统。

在组件层设置 [布局指南](layouts.md) 的颜色角色：深蓝标题及主流程、黑色正文、深色块白字、按需设置的深红底部结论，白底与中性边框允许。去掉模板自带的淡色或马卡龙填充及装饰；原始图件和科学数据色阶不按主题强制换色。

生成前先检查分页：同一任务的互补方法、结果和解释能否在可读字号下组成一页。禁止把可合理整合的内容拆成多张空框页，禁止用缩字或装饰填补稀疏。素材不足时按素材指南主动寻找相关图件，或合并、精简页面。封面与章节入口应有核心路线或主题综合视觉，结束页保持明确收束。

页脚和模块组件不得预置通用“备注/说明/免责声明”字段或自动附加限制句；页脚只按实际需要放页码和必要署名。需要解释科学内容时，明确写入相邻正文或图表标注，不调用一个默认小字说明组件。

文字、基本图形和连接线优先原生可编辑；数据图在兼容性允许时使用原生图表或保留可重绘数据。结构图和复杂科学图可以是高质量矢量或栅格图，附源文件。不要为了全部可编辑而改变数据表达。

长篇制作可并行整理来源或分章起草，但主负责人统一模板、术语与页码。交付审查由未参与该部分制作的 Agent 执行会增加独立性；不可用时自行按同一验收清单复核，不虚构独立审查。

## 三项验收相互独立

### 科学内容

逐个主张对照证据身份，核对数字、单位、对照和必要限定。检查不同页面及备注的术语、进展状态、实验/预测身份是否一致。按 [图件与证据](figures-evidence.md) 核对新增素材的原图、图注与来源索引；使用生图模型的图件核对其明确授权及适用范围。换图后同步更新引用与讲稿。

### 实际画面

新稿或大改版查看全稿缩略图和每页实际渲染；局部修改检查改变的页及受排版/逻辑影响的相邻页。逐页至少回答：

1. 能否迅速读出主问题或主判断？模块是否共同服务它？
2. 图像在模块中是否足够大？坐标、标签与对象是否可读？有无纯装饰填充？
3. 标题、正文、模块结论、全页结论是否层级清楚？长句是否挤压图像？
4. 文字有无溢出、遮挡、错字、替代字体、孤字或标点独占行？优先精炼措辞或调整文本框与换行，不默认缩小字号。图片有无失真或误裁？
5. 箭头是否醒目、居中且语义正确？括号是否涵盖所有汇总对象？
6. 讲稿是否能按画面顺序讲通？状态与总结是否处于合适层级？
7. 放大检查左下角、整页底部，以及每个模块、图片和表格下方。逐条读小字：它是否属于制作解释、泛泛免责或重复限定？是否被改称“提示/说明/备注”而保留？遇到此类文字直接修正，不能只靠关键词扫描，也不能只看全稿缩略图。
8. 是否仍有大面积无功能留白，或同一任务被拆成多张稀疏页面？合并互补证据后是否更容易比较，字号和图像是否仍可读？封面、章节入口和结束页是否分别完成定位、定向与收束？
9. 标题和主流程是否深蓝、正文是否黑色、深色块内是否白字、设置的关键底部结论是否深红？模板是否带回淡色或马卡龙装饰？科学色阶和原始图件颜色是否仍保持意义？

每条必要科研条件都应进入相邻主句或正常字号的解释，不能把失真的强结论留在大字、再靠底部小字修补。页码、必要引用、许可署名和真正的图表标注不属于防御性说明。制作与验收信息只进入对用户的交付说明或独立记录。

发现问题后修正并重渲染受影响页。结构检查通过或未报重叠不等于视觉检查通过。

### 文件结构

从本技能根目录运行：

```bash
python scripts/audit_pptx.py /path/to/deck.pptx --require-notes --expected-slides 12 --output /path/to/audit.json
python scripts/audit_slide_rules.py /path/to/deck.pptx --output /path/to/slide-rules.json
```

`12`仅示例，填写该稿预期页数或省略此参数。审计只读文件，检查实际演示顺序、关键关系、备注及媒体/图表记录。其字体统计只包括显式声明，不能代表继承后的最终字体。需要验证图表数值时，另将导出后的图表值与源数据逐项比较。

脚本的退出码和报告检查范围一起解释；不要把结构成功称为“排版通过”或“在PowerPoint中测试通过”。备注缺失要修复，用户要求不提供讲稿时不加`--require-notes`。

`audit_slide_rules.py` 提供逐页文字与字体检查，定位已知防御性短语和字体不符项。查到防御性表达后删除无用说明；若承载真实限制，重写相关科研主句并保留证据强度。未解析继承字体及其他待复核项必须核实，不能当作通过；也不要为了让检测变绿而篡改必要科学条件。脚本不做OCR、不穷举同义句，图片内小字、语义和实际字形仍由逐页审核补足。用户明确指定其他字体时才使用脚本的字体参数。

该脚本的退出码必须按下表处理：

| 退出码 / 状态 | 含义与后续动作 |
|---|---|
| `0 / pass` | 在脚本覆盖范围内未发现问题；仍须完成实际画面与语义审核，不能据此宣称全稿无问题 |
| `1 / fail` | 存在错误；定位并修正，再运行检查，不能直接交付为已验收 |
| `2 / needs_review` | 有脚本不能决定的事项；逐条人工或用适用工具核对，记录依据及结论，不等同失败也不等同自动通过 |

对 `needs_review` 建立独立复核记录，至少定位到文件、页和对象，写明检查方式、观察及处理结果。例如实际查看图片内是否有防御性小字，核对专业符号字形与限域字体，或解析主题继承后的字体。记录绑定最终文件版本；修改后重渲染受影响页并重跑检查，未解决项如实保留。图片或专业符号在人工检查后可以关闭对应问题，但原始报告仍可为 `2 / needs_review`：此时表述为“脚本待复核项已人工核验”，不得改报告、屏蔽检查或宣称“脚本返回0”。这些审计记录另存，不附在幻灯片底部或讲稿中。

## 交付前冻结

生成一份待交付文件，审阅其渲染，再核对正式路径中的同一文件。可用哈希或逐页渲染比对防止交付错版；正常情况下不需要为每次小改建立全量备份。

PPT、PDF预览和独立讲稿如均交付，应保持页码、标题、图件和讲稿一致。来源索引与必要制作源文件另存，检查不存在占位文本、测试数据混入、私人路径或非公开备注。

报告实际通过的检查和剩余限制。保留需要复现、审阅和恢复的文件；清理本轮可重建缓存，原始数据与用户文件按已有授权处理。

## 可移植边界

核心入口遵循 [Agent Skills 格式](https://agentskills.io/specification) 的 Markdown 与 YAML frontmatter，参考材料从技能根目录解析。`agents/openai.yaml`仅为Codex界面适配，其他Agent无需执行它。脚本只依赖Python 3标准库，不使用工具专用标记、绝对路径或自动安装逻辑。兼容格式不等于每个Agent都自带PPT生成或渲染能力。

## 维护参考库

用户使用技能时按 [参考文件使用说明](template-use.md) 读取可编辑PPT、逐页布局JSON与预览，无需运行生成脚本。维护者可用 `python scripts/build_reference_library.py` 重新生成37张SVG及选择索引；它只依赖标准库，不会更新PPT或PNG。修改设计后同步更新原生PPT与逐页布局JSON，用 `python scripts/enrich_reference_layouts.py` 更新模块成员和关系，再从最终PPT导出1280×720的PNG并逐页审阅。不能把SVG渲染当成PPT导出验收。

`assets/reference-library/render-manifest.json` 记录各文件SHA-256及实际渲染器，测试检查源文件、PPT、JSON与预览是否为已配对的版本。哈希检查只能发现文件不同步，不能替代视觉审核。

公开参考库仅包含原创合成示例。原始报告、审阅记录和来源页面对应表留在获授权的项目范围内，不随技能发布。
