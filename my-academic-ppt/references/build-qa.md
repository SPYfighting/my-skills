# 实现与验收

## 按能力选择工具

先检查当前环境，而不是假定特定软件可用。Codex 有演示工具或依赖发现入口时优先使用；其他 Agent 选择实际可用的编辑器或生成库，例如 PowerPoint、LibreOffice、PptxGenJS、python-pptx 或环境提供的制稿接口。工具名称是选择示例，不是安装要求。首次使用或关键行为不确定时核对匹配版本的官方文档。

写入与渲染分别验证：一个库能生成PPTX不代表能把它正确渲染。渲染可来自演示软件导出、可靠的服务或现有工具；保留未能验证的字体、图表或格式差异。工具不足时交付已完成且可读的部分并说明缺口，不把逐页图片或HTML称为已完成的可编辑PPT。

字体不预设本机路径。按目标语言检查字体可用性与替代，试渲染包含中英文、公式、数字和强调字重的代表内容。缺少字体时选合适替代并复核换行，不自动下载未知字体包。

## 制作方式

建立少量可复用组件：标题、章节入口、图文模块、粗箭头、重点结论、页码。用统一坐标、颜色和字号控制全稿，局部内容驱动组件大小，避免为每页另造视觉系统。

文字、基本图形和连接线优先原生可编辑；数据图在兼容性允许时使用原生图表或保留可重绘数据。结构图和复杂科学图可以是高质量矢量或栅格图，附源文件。不要为了全部可编辑而改变数据表达。

长篇制作可并行整理来源或分章起草，但主负责人统一模板、术语与页码。交付审查由未参与该部分制作的 Agent 执行会增加独立性；不可用时自行按同一验收清单复核，不虚构独立审查。

## 三项验收相互独立

### 科学内容

逐个主张对照证据身份，核对数字、单位、对照和必要限定。检查不同页面及备注的术语、进展状态、实验/预测身份是否一致。按 [图件与证据](figures-evidence.md) 核对新增素材的原图、图注与来源索引；使用生图模型的图件核对其明确授权及适用范围。换图后同步更新引用与讲稿。

### 实际画面

新稿或大改版查看全稿缩略图和每页实际渲染；局部修改检查改变的页及受排版/逻辑影响的相邻页。逐页至少回答：

1. 能否迅速读出主问题或主判断？模块是否共同服务它？
2. 图像在模块中是否足够大？坐标、标签与对象是否可读？有无纯装饰填充？
3. 标题、正文、模块结论、全页结论是否层级清楚？长句是否挤压图像？
4. 文字有无溢出、遮挡、错字、替代字体、孤字或标点独占行？优先精炼措辞或调整文本框与换行，不默认缩小字号。图片有无失真或误裁？
5. 箭头是否醒目、居中且语义正确？括号是否涵盖所有汇总对象？
6. 讲稿是否能按画面顺序讲通？状态与总结是否处于合适层级？

发现问题后修正并重渲染受影响页。结构检查通过或未报重叠不等于视觉检查通过。

### 文件结构

从本技能根目录运行：

```bash
python scripts/audit_pptx.py /path/to/deck.pptx --require-notes --expected-slides 12 --output /path/to/audit.json
```

`12`仅示例，填写该稿预期页数或省略此参数。审计只读文件，检查实际演示顺序、关键关系、备注及媒体/图表记录。其字体统计只包括显式声明，不能代表继承后的最终字体。需要验证图表数值时，另将导出后的图表值与源数据逐项比较。

脚本的退出码和报告检查范围一起解释；不要把结构成功称为“排版通过”或“在PowerPoint中测试通过”。备注缺失要修复，用户要求不提供讲稿时不加`--require-notes`。

## 交付前冻结

生成一份待交付文件，审阅其渲染，再核对正式路径中的同一文件。可用哈希或逐页渲染比对防止交付错版；正常情况下不需要为每次小改建立全量备份。

PPT、PDF预览和独立讲稿如均交付，应保持页码、标题、图件和讲稿一致。来源索引与必要制作源文件另存，检查不存在占位文本、测试数据混入、私人路径或非公开备注。

报告实际通过的检查和剩余限制。保留需要复现、审阅和恢复的文件；清理本轮可重建缓存，原始数据与用户文件按已有授权处理。

## 可移植边界

核心入口遵循 [Agent Skills 格式](https://agentskills.io/specification) 的 Markdown 与 YAML frontmatter，参考材料从技能根目录解析。`agents/openai.yaml`仅为Codex界面适配，其他Agent无需执行它。脚本只依赖Python 3标准库，不使用工具专用标记、绝对路径或自动安装逻辑。兼容格式不等于每个Agent都自带PPT生成或渲染能力。

## 维护参考库

用户使用技能时按 [参考文件使用说明](template-use.md) 读取可编辑PPT、逐页布局JSON与预览，无需运行生成脚本。维护者可用 `python scripts/build_reference_library.py` 重新生成37张SVG及选择索引；它只依赖标准库，不会更新PPT或PNG。修改设计后同步更新原生PPT与逐页布局JSON，用 `python scripts/enrich_reference_layouts.py` 更新模块成员和关系，再从最终PPT导出1280×720的PNG并逐页审阅。不能把SVG渲染当成PPT导出验收。

`assets/reference-library/render-manifest.json` 记录各文件SHA-256及实际渲染器，测试检查源文件、PPT、JSON与预览是否为已配对的版本。哈希检查只能发现文件不同步，不能替代视觉审核。

公开参考库仅包含原创合成示例。原始报告、审阅记录和来源页面对应表留在获授权的项目范围内，不随技能发布。
