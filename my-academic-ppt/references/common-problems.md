# 常见问题：从症状定位到可验收的修正

本页用于处理首轮样稿、用户反馈和最终渲染中的典型失败。先在下表定位，再读对应条目；修复实际出现的问题，不把所有修正叠加到每一页。配图、分栏、粗箭头、红色结论及章节页都是表达手段，是否采用由科学关系和当前任务决定。

| 检索症状 | 条目 |
|---|---|
| 像参考却达不到参考效果；整稿套同一模板 | 01、02 |
| 空洞、字多图少、图缩成小点、流程太简单 | 03–06 |
| 跨专业听众看不懂；措辞像宣传文案 | 07、08 |
| 图片有明显生成感；箭头、括号关系不清 | 09–11 |
| 字体杂乱、对齐不齐、结论像脚注 | 12–14 |
| 章节页单薄、进展抢标题、缺少收束 | 15–17 |
| 外部文献喧宾夺主；备注不能直接讲 | 18、19 |
| 预测写成结果；免责声明到处都是 | 20、21 |
| 改好一处又破坏其他页；版本越积越多 | 22 |

## 01｜只复制了分栏，却没有学到参考页的信息组织

- **适用与例外：** 有风格参考、用户已认可页面或正在建立视觉范例时使用。粗线框适合内部讨论布局位置，不作为完整效果的唯一参考。
- **症状：** 栏数、配色相近，但每栏只剩标题和几行字；参考页的主次、图像比例、证据联系及阅读节奏消失了。
- **原因：** 只提取文字或截图轮廓，未分析参考页面中每个元素承担什么解释任务。
- **修正：** 实际查看参考页，记录主判断、视觉焦点、图文配比、模块关系、比较轴、结论位置。重新制作时用当前任务的内容填充这些功能。用于公开复用的示例采用通用自绘或明确标记的合成内容，保留真实的排版复杂度，不复制私人材料。
- **验收：** 将参考与新页并排查看，能指出哪些阅读关系得到继承、哪些因新内容而改变。示例中的图像、说明、标签和结论均达到可投影阅读的完成度；不能只凭“同样有几个框”判定风格一致。

## 02｜把参考版型当成所有页面都必须遵循的模板

- **适用与例外：** 新报告包含多种论证任务、整稿节奏单一时使用。连续的可比结果采用同一版型，有利于听众逐项比较。
- **症状：** 单一主图也被切成等宽卡片；每页都有底部结论、照片或箭头；为凑固定栏数而重复内容。
- **原因：** 在明确本页科学关系之前决定容器，误把一致性理解为构图相同。
- **修正：** 先判定本页是过程、比较、机制、主证据、整体与局部、阶段推进还是综合归纳，再到[布局指南](layouts.md)选择、混合或新建构图。统一字体、颜色角色、边距及标签方式，让面积随证据权重分配。
- **验收：** 每个主要空间分区都对应不同的解释作用；取消某个装饰性组件后若意思更清楚，就保留更简洁的版本。全稿统一但能看出内容角色的变化。

## 03｜“信息充实”被做成空框，或被误解为把文字塞满

- **适用与例外：** 研究方法、进展、比较及综合页显得空洞或拥挤时使用。开场、转场和结束页可以主动留白。
- **症状：** 框内只有名词，讲者要补充大量背景；或反过来，说明密集到必须缩小字号才能放下。
- **原因：** 没有区分必要解释与重复措辞，也没有让图形承担内容。
- **修正：** 按本页问题补齐缺少的角度，例如对象、关键操作、评价依据和可检验产出；用真实比较、图件或关系替换空泛句子。删去同义重复；确有多个独立问题时拆页，把只供追问的细节转入附录。
- **验收：** 听众能从页面与讲稿获得完成本页推理所需的信息，字号不因填满页面而下降。图、短句和留白各有作用，不能用模块数量或填充比例代替判断。

## 04｜已经分了很多块，仍然是纯文字卡片堆叠

- **适用与例外：** 内容涉及可视对象、过程、结构、空间关系或实验结果时使用。定义对照、决策条件和精简表格可主要依靠文字。
- **症状：** 不看标题，各模块外观几乎相同；文字描述了一个过程，却没有帮助听众形成直观印象。
- **原因：** 图片被视为装饰，未给它分配解释任务。
- **修正：** 给需要视觉解释的模块配置对应小图：对象概貌、操作示意、结构局部、变化曲线、比较面板等。缺少素材时按 [图件与证据](figures-evidence.md) 主动检索文献或公开图件，选取可复用的相关面板，配紧贴该图的短说明。图无法增加理解时保留紧凑文字或表格，不硬塞图标。
- **验收：** 能回答每张图具体帮助理解什么。去掉图片会损失一种解释，去掉重复文字则不损失内容；每个模块不必拥有相同数量或类型的图。

## 05｜图片框很宽，但真正的图像缩在中央

- **适用与例外：** 横向图像区出现大面积无意义留空、局部标签看不清时使用。科学比较需要统一比例尺或原始构图时，不能为了铺满而任意裁剪。
- **症状：** 图像文件看似占满框，科学对象却很小；图片两侧空白远大于有效内容。
- **原因：** 按文件边界适配图片，没有检查图内的透明边缘、白边和对象方向。
- **修正：** 裁去无信息边缘；按科学意义选择横向裁切、主图与局部放大、相关小图组合，或重新绘制适合该宽高比的示意图。只有方向不承载意义时才旋转对象；保留比例，不拉伸。调整模块形状往往比继续放大源图更有效。
- **验收：** 在正常放映尺寸可辨认主体和关键标签，原有坐标、方向、尺度及必要上下文完整。检查的是有效科学内容的大小，不只是图片对象的外框尺寸。

## 06｜技术路线只有方框箭头，没有科学内容

- **适用与例外：** 需要向听众解释研究如何实施时使用。章节入口可以极简，但详细方法页不能停留在同样的抽象层次。
- **症状：** 节点只写“输入、分析、验证”，或堆了多个工具名；看不出输入怎样变成可检验的结论。
- **原因：** 把过程词当作方法解释，省略了筛选依据、输出和反馈信息。
- **修正：** 在关键节点放入对象或证据小图，并用短语交代该步作用、评价条件和产出；并行方法分支进入共同筛选，验证后回到真正需要更新的步骤。将当前结果能支持的路线与后续计划分别表达，避免为图形完整而补造已完成步骤。
- **验收：** 沿图讲述时，能解释每一步“接收什么、做什么、交付什么”，关键筛选与实验验证如何连接。箭头有实际语义，页面可讲通，不依赖听众熟悉工具缩写。

## 07｜技术细节正确，跨专业听众仍然无法理解

- **适用与例外：** 面向相邻学科、综合评审或非执行者汇报时使用。方法学专题、复现培训和关键控制条件可以保留更细层级。
- **症状：** 主流程被文件格式、底层编码、去重细则、参数缩写挤满；听众记住术语，却不知道它解决什么问题。
- **原因：** 按实现步骤写报告，没有按听众要做的判断选择细节。
- **修正：** 正文优先说明数据从哪里来、质量怎样控制、模型或方法起什么作用、输出如何检验。将底层操作归纳为其科学功能，如“减少重复记录、提高训练数据可靠性”；只有直接改变结论可信度或区分方法的细节才展开，其余移入讲稿或附录。
- **验收：** 非执行者能够复述研究目的、主路线和成功判据。精简后仍保留影响解释的控制与条件，不把真正的创新压成没有信息的“智能分析”。

## 08｜措辞像产品宣传，或为了显得专业而堆术语

- **适用与例外：** 科研标题、模块说明和全页结论出现泛泛评价时使用。封面和转场可以概括，但应能由后续内容具体展开。
- **症状：** 大量使用“赋能、突破、智能、高效”等词，却没有对象、作用或可观察结果；同一方法在不同页不断换名字。
- **原因：** 用评价替代研究判断，或沿用了素材中的口语、简称和营销用语。
- **修正：** 用“研究对象＋具体方法/问题＋可观察变化或目标”重写。参数化地说明快在哪里、改了什么、依据何种比较；尚无量化证据时写目标或进展。统一核心术语，首次出现的跨领域概念用一句作用说明。
- **验收：** 每个评价词都有本页或前文可定位的依据；标题、图注和讲稿的确定程度一致。朗读自然，专业名词没有超过表达该判断的需要。

## 09｜配图有圆润、糖果色、拟物光泽等明显生成感

- **适用与例外：** 正式科研报告中的概念插图风格突兀时使用。科普、教学或用户要求的卡通风格可以更活泼，素材获取仍遵循 [图件与证据](figures-evidence.md) 的检索与生图授权规则。
- **症状：** 物体膨胀圆滑、配色清亮而无功能、背景有无意义渐变；手部或复杂仪器细节吸引注意，却不参与解释。
- **原因：** 通用插画风格压过了科学对象与整稿视觉语言，生成素材未经科学和风格复核。
- **修正：** 优先检索并换为可复用的研究图或真实对象素材，再用准确的原生示意和线图组织关系。仅在已获明确生图授权时，才为概念插图指定对象关系、克制配色和科学插图风格；文字与数据另用可编辑元素制作。不要通过美化抹平实验图的真实差异。
- **验收：** 先检查部件和连接的科学合理性，再比较整稿色调、线条与质感。插图承担清楚的说明任务，与证据图不混淆；即使美观，也不能替代数据或结构证据。

## 10｜箭头太细、贴着文字，或整条短路线偏向一侧

- **适用与例外：** 目录短路线、章节步骤和主要流程需要在投影中迅速辨认时使用。次要引线、坐标辅助线及精细结构标注可采用较细线条。
- **症状：** 箭头在放映时近乎消失，箭头头部贴住右侧文字，几组词和箭头看起来整体偏移。
- **原因：** 只计算文本框坐标，忽略框内留白和实际字形宽度；线型未按展示尺度检查。
- **修正：** 为主要流程选可见的实心箭身，按相邻模块尺度调整。以两段可见文字或图形的边缘定义空隙，将箭头整体放在空隙中央，两端留距；再把整组路线作为一个视觉单元居中。文字长度不同，不要求文本框宽度相同。
- **验收：** 在正常放映尺寸看得见箭身；箭头到两端内容的间隔视觉均衡；短路线与其所属标题或容器对齐。几何定位完成后仍要看实际渲染，避免字体留白造成视觉偏差。

## 11｜括号、加号或环形装饰表达了错误的关系

- **适用与例外：** 多组贡献汇合、资源互补或反馈关系需要归纳时使用。真正的循环过程可以用环形，独立并列内容可无需连线。
- **症状：** 声称汇总所有模块，括号却只罩住其中一组；中央大圆占据版面，但看不出各部分怎样联系。
- **原因：** 先加连接装饰，再决定它代表什么；把“有关联”误画成循环或先后关系。
- **修正：** 先写明关系是相加、汇合、支持、先后还是反馈，再选择符号。汇总括号的范围覆盖所有被归纳模块；加号放在真正合并的两组之间；反馈线注明回传信息。关系复杂时可用对应矩阵、分层接口或少量标注连线替代大圆。
- **验收：** 不读讲稿也能判断哪些内容被归为一组、信息往哪里走。每个符号只有一种明确语义，没有因为构图方便而暗示不存在的因果或闭环。

## 12｜字体杂乱，或字号数字统一但视觉仍不统一

- **适用与例外：** 汇集多个来源、跨工具生成或替换字体后使用。公式、专业符号及必要的等宽内容可以使用适合的补充字体。
- **症状：** 中文、英文和数字质感不协调，同一级标题大小忽强忽弱；导出后出现字形替换、孤字或意外换行。
- **原因：** 沿用素材原始字体，混淆生成工具单位，或只检查源代码中的字号。
- **修正：** 用少量字体与明确角色管理标题、正文、图标注和结论；按目标系统检查实际字体及替代。对混合中英文、公式和强调字重做代表页试渲染。放不下时先改句子、框宽或构图，再考虑字号。
- **验收：** 同类元素在实际成品中拥有相近视觉重量；字体替代与换行已检查。具体尺寸以[布局指南](layouts.md)为起点并按显示效果调整，不能把统一数字当成统一观感。

## 13｜分栏底部参差不齐，虚线框又把页面切得太碎

- **适用与例外：** 多栏比较、图文模块或重复组件页使用。长段叙述宜左对齐；数值表格按比较方向对齐，不必全部居中。
- **症状：** 栏底短结论靠左、位置高低不一；框线嵌套过多，图片、说明和结论像互不相关的小盒子。
- **原因：** 逐个摆放模块，没有共享图像区、说明区与结论区的基线；边框替代了真正的分组。
- **修正：** 为同类模块设共同的标题、图像和底部结论区；短结论相对各自模块居中，并检查换行后的总高度。需要虚线时用一层边界收拢关联的图文；靠间距或浅背景已能分组的区域可去框。
- **验收：** 沿横向扫读时，同层元素形成稳定基线；短结论不会与上方正文混为一体。不同长度的说明仍有合理间距，边界数量没有超过实际分组需要。

## 14｜整页最重要的一句被做成小号脚注

- **适用与例外：** 页面另设全页结论、意义或行动句时使用。标题已清楚承载主判断，可省略重复的底部句子。
- **症状：** 结论虽然用强调色，字号却比正文还小；两行挤在一起，或被页码、来源及装饰线包围。
- **原因：** 把剩余空间分配给主结论，误认为颜色能补偿尺寸不足。
- **修正：** 先为主结论保留独立区域，再布置主体内容。提炼成能一眼读完的判断，必要时删除重复第二行；字号、字重和周围留白共同突出它。超过一行时调整行距与框高，不压缩到边界。
- **验收：** 正常放映时结论至少不弱于正文，能与模块结论区分；颜色不是唯一强调手段。底部文字不遮挡图件，也没有为腾位置牺牲关键证据的可读性。

## 15｜章节首页只剩几行口号，标题反而比右侧流程弱

- **适用与例外：** 报告较长、章节需要独立转场时使用。短报告可直接在内容页说明主线，无需章节页。
- **症状：** 左侧标题很小，下面堆几句抽象说明；右侧流程很大，却没有指出本章要回答什么。
- **原因：** 章节页被当作填充页，未承担定向任务；标题与核心路线没有层级。
- **修正：** 以醒目主标题交代本章研究任务，用最简真实路线说明从对象、关键方法到检验或产出；若有能力或方法贡献概括，用一句清楚的话承接。路线可竖向、横向或嵌入主图，按标题长度和对象关系布置。
- **验收：** 进入章节时能迅速知道研究什么、如何推进、将看到哪类证据。标题足以与流程平衡，章节页比方法详解更简洁，但仍有明确内容。

## 16｜研究进展标签放在标题附近，抢占主线或反复出现

- **适用与例外：** 报告需要区分已完成、正在检验和未来工作时使用。若进展状态就是本页核心判断，可放入主标题或主图，而非刻意弱化。
- **症状：** 状态标签悬在标题与路线之间，打断阅读；每页重复同一句状态，挤占内容。
- **原因：** 未区分章节身份信息和本页科研判断。
- **修正：** 通常在章节入口或阶段总览写一次，与主线说明分层，放在概括语之下、左下方等稳定的次要区域。用听众语言写已确认的状态；进展改变时同步更新相关正文和讲稿。
- **验收：** 阅读顺序先到标题与核心路线，再到状态；状态不与红色或其他强调色的主判断争抢位置。同一工作在全稿中的阶段表述一致，状态没有被美化成未经证实的成果。

## 17｜目录没有推进逻辑，总结仍挂在最后一章下面

- **适用与例外：** 多部分报告需要导航与收束时使用。短分享、单页说明或只交付局部页面可省略目录、独立总结及致谢。
- **症状：** 目录是互不相连的主题清单；末尾已经概括全报告，却仍用最后一章子编号；报告停在某项细节后突然结束。
- **原因：** 页码结构来自制作顺序，未区分章节内容与全稿结论。
- **修正：** 目录用章节任务或短路线提示各部分怎样推进主问题。总结独立于末章，综合证据、意义和下一步关键动作，不只重复目录。按场合设置简洁致谢或讨论邀请，称谓与用途一致。
- **验收：** 目录与正文范围相符；总结确实覆盖整稿且没有新增未经展开的结果；最后一页给出明确结束信号。没有为了仪式完整而给短报告强加多张空页。

## 18｜引用外部方法，却专门讲了无关结果；来源又进入演讲正文

- **适用与例外：** 借助文献解释方法、补充示意或比较研究时使用。文献综述和结果对比报告本来就需要讲外部研究，应保留相应篇幅。
- **症状：** 一张仅用于解释流程的小图被扩成外部论文汇报；图旁充满“文献图、仅参考”等重复标签；讲稿夹着题名、网址和素材说明。
- **原因：** 没有区分图片的解释用途、结果归属和来源记录。
- **修正：** 直接讲该方法对当前问题的作用，只保留完成解释所需的面板。来源详情存入独立索引；讲稿只保留口头正文。页内必要引用、许可署名以及外部结果身份仍按[图件与证据](figures-evidence.md)保留，普通示意无需叠加无意义免责声明。
- **验收：** 听众能区分本研究证据、外部结果和方法示意；索引能定位使用的来源与处理方式；讲者照读备注时不会读出文件名、网址或制作说明。画面简洁与出处真实同时成立。

## 19｜备注像提纲或指令，非执行者拿到后仍然不会讲

- **适用与例外：** 需要逐页讲稿，尤其由未直接参与全部研究的人汇报时使用。熟练讲者明确要求提词卡时可改用短句提示。
- **症状：** 备注以“本页讲稿、你可以这样讲”等标签开头；只复述屏幕文字；说出讲者实际没有经历的实验或个人贡献。
- **原因：** 没有围绕看图顺序写口头语言，也没有核对讲者与研究之间的关系。
- **修正：** 从本页问题自然起笔，解释图上看哪里、比较什么、结果说明什么，再连接下一页。首次必要术语简短解释。采用与证据及实际参与关系匹配的主语，不虚构亲历；资料来源和制作提示移出备注。
- **验收：** 逐页朗读能顺着画面讲通，句子长度适合口头表达，指代对应清楚。未执行研究的讲者也能理解方法作用；备注没有超出页面和证据的个人归功或结果断言。

## 20｜模型分数被讲成真实性能，进行中的路线被讲成已有结果

- **适用与例外：** 任何含计算输出、代理指标、外部证据或计划的科研报告均应核对。已有直接验证时可以明确报告结果，不需无谓弱化。
- **症状：** 预测排名被写成实验提升；检测信号被直接称为目标性质；未给出测量数据却配上结果式标题或示意曲线。
- **原因：** 在增强叙事和美化图件时丢失了证据身份，或把用户提供的阶段信息扩展为未提供的结果。
- **修正：** 对照来源记录，分别使用“预测、测得、观察到、正在检验、计划”等准确动词。说明代理指标与目标量的关系及需要的验证。缺结果时呈现已完成步骤、筛选标准和下一项实验；示意图不承载虚构数值。
- **验收：** 标题、图内标注、图注与讲稿的证据等级一致。每个数值和进展状态有来源；换掉某个动词不会使主张超出证据。相关限定留在读者看到该判断时能获得的位置。

## 21｜页面充满防御性小字，研究主线被“尚未、仅供、不能”淹没

- **适用与例外：** 制作说明或反复免责声明侵入正文时使用。会改变结论解释的实验条件、预测身份及安全限制必须清楚保留。
- **症状：** 每页角落都有宽泛免责句；底部主结论总在说明缺少什么；相同边界在标题、正文、脚注和备注反复出现。
- **原因：** 把制作过程中的不确定性全部交给观众，未区分实质限定与无助理解的自我保护。
- **修正：** 禁止把“为什么这样制作”、泛泛免责或重复限定加入正文、角落小字及页脚；已有内容直接删除。将实质限定贴近相关主张并说明一次。用准确动词承载确定程度；未完成工作连接到下一项可检验动作。证据冲突或缺口仍如实处理，不通过删免责声明掩盖它们。
- **验收：** 每条保留的限定都能回答它改变了哪项结论的解释；重复文字已合并。听众先读到研究问题与进展，同时不会把计划、示意或预测误当已完成证据。

## 22｜修订破坏已认可设计，或交付了未检查的旧版本

- **适用与例外：** 连续多轮反馈、多人并行制作或存在多个导出文件时使用。用户明确要求重构时，可以调整全稿，但应重新验收受影响范围。
- **症状：** 调整箭头却更换了原配图，修改一页导致字号全稿变化；文件名很多、来源不明，PPT、预览和讲稿不一致。
- **原因：** 没有把反馈限定到可核对对象；缺少统一源文件和交付冻结步骤。
- **修正：** 先将反馈定位到页面、组件和需要改变的属性，继承已认可元素。共享组件变动时检查全部受影响页；小改以局部差异为主。按明确恢复需要保留版本，正式交付前冻结文件，检查其实际渲染与附带讲稿；详细流程见[实现与验收](build-qa.md)。
- **验收：** 已修改内容对应本轮要求，未涉及页面无意外变化；最终路径中的文件就是已审阅版本，页数、标题、图件与讲稿相互一致。保留必要源文件与恢复副本，清理本轮可重建的缓存和重复导出，不删除原始资料或用户要求保留的版本。
