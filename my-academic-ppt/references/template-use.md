# 使用可编辑参考 PPT

## 三种互补入口

- **主要参考：[科研汇报布局参考.pptx](../assets/reference-library/科研汇报布局参考.pptx)**。37页，每页对应一种完整组合。文本、框线、箭头及主要图形可编辑；复杂局部裁剪图保留为图件。示例的科学内容和数据均为原创合成，用于学习组织方法，不是研究成果。
- **选择与预览：[页面索引](gallery.md)**。先按信息关系定位相关页，再看对应的PPT导出画面。预览用于看效果，不能代替PPT源结构。
- **无视觉入口：`assets/reference-library/layouts/`**。每页独立JSON，与PPT页码对应，包含用途、阅读顺序、可变形建议、模块成员与模块关系，以及元素文字、坐标、层叠顺序、字号、字体、颜色和对齐属性。坐标单位明确记录；不要把像素字号直接当PowerPoint磅值。

## 没有视觉能力时怎样用

1. 从 `assets/reference-library/catalog.json` 选与当前科学关系相近的页。需要串行过程、并行筛选、主证据、局部放大或反馈系统时，按关系选择，不按标题里的学科名选择。
2. 读取该页JSON，先看用途、阅读顺序、`regions`与`relationships`。`member_ids`列出模块中的原生元素，便于按组移动；跨模块连线和全页背景保留在`unassigned_element_ids`中，需要单独调整。再查看标题、正文和关系图形的属性。用现有PPT编辑器或解析工具核对实际文本及元素，不能只依据预览文件名推断布局。
3. 在新文件中复用选定页的布局骨架，替换文字和图件。调整内容长度时同步调整文本框、模块间距与箭头位置；科学对象、数据和进展必须来自当前任务，不能沿用示例结果。
4. 可改栏数、比例、排序、字号、框线和结论区，也可以组合多个参考或新建构图；颜色按 [布局指南](layouts.md) 的强制角色处理，不能从模板继承淡色主题。同一任务的互补结果优先同页整合，保留真正需要的对齐关系与证据层级，不冻结坐标或照抄示例密度。
5. 做文件结构、文本完整性与几何检查，并尽可能让有视觉能力的工具或审阅者检查实际导出。没有视觉检查时明确实际验证范围，不能将JSON无越界等同画面美观。

只读取相关一页，避免一次加载数千个无关元素。从技能根目录运行以下命令可将该页说明导出为UTF-8 JSON，供文本工具读取：

```bash
python scripts/read_reference.py --page 37 --output /path/to/layout-37.json
```

默认输出模块与文本摘要；需要完整绘图几何时加`--full`。`--list`列出页码与用途；不指定`--output`时输出为ASCII转义JSON，便于跨终端传输。

## 编辑与字体

参考文件中文使用微软雅黑（Microsoft YaHei），英文和数字使用 Times New Roman。混排与缺字体的处理遵循 [布局指南](layouts.md) 的强制规则，不能从参考文件或系统自动替代反推可任意换字体；不随技能分发商业字体文件。PPT图形中的曲线为可编辑示意线条，并不等于含原始工作簿的统计图。真实数据图应从当前任务的数据重新绘制或插入获授权的原图。

图册中的程序绘图示范布局组织。制作实际报告时，按 [图件与证据](figures-evidence.md) 主动寻找当前主题的文献及图片素材，不能默认沿用合成示例；是否调用生图模型也按该指南判断授权。

参考页是可变形的组织范例，不是任意配色或留空的授权。新页执行深蓝标题与主流程、黑色正文、深色块白字，以及按需设置的深红底部结论；原始证据颜色与科学色阶保持意义。每页内容应与任务相称：资料多时整合比较，资料少时补充相关图件或合并精简，不能复制空框来填页。封面和章节入口也应有主题视觉或核心路线，结束页保持收束作用。

参考页不放制作说明或免责页脚。合成身份集中在本说明及文件元数据中说明；实际汇报中的数据身份、关键条件和必要署名仍应准确表达。
