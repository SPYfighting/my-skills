# My Academic PPT

把科研内容做成能讲清楚、能看明白、能核对证据的演示文稿。组织原则是**围绕一个清楚的问题或判断，提供足够的视觉解释与证据，建立明确的阅读层级**。多模块只是其中一种组织方式。

## 强制规则

- **默认字体：中文用微软雅黑（Microsoft YaHei），英文和数字用 Times New Roman。** 除非用户明确指定其他字体，否则必须执行；参考模板、生成库默认值或本机字体缺失不能自行改写此规则。混排按文字片段或中西文字体槽设置，涵盖标题、正文、图表标注及备注；实现细节见 [布局指南](references/layouts.md)。
- **配色采用深色信息层级，禁止淡色系或马卡龙主题与装饰。** 白底允许；标题和主流程用深蓝，正文用黑色，深色块内用白字，设置关键底部结论时用深红。模板和生成库默认值不能覆盖这些角色；不强制每页增加底部结论。原始证据颜色及有科学含义的数据色阶保留，具体配色见 [布局指南](references/layouts.md)。
- **每页内容必须充实，禁止大面积无功能留白。** 内容页优先将同一研究任务的多角度结果、方法和解释合理整合，不拆成多个稀疏空框页。保持可读，不靠缩字、无关图形或装饰填满。材料不足时主动找文献图件，或合并、精简页面；封面与章节入口须有主题综合视觉或核心路线支撑，结束页按收束用途处理。
- **禁止页内防御性说明。** 左下角、整页下方、各模块/图片/表格下方及其他位置，都不得出现制作解释、泛泛免责或重复限定的小字备注。不能换位置、改名称、缩小或淡化后保留，也不能改成大字绕过禁令。发现即删除或重写相关主句，修正后再交付；实质科研条件和必要署名的处理见 [图件与证据](references/figures-evidence.md)。

## 设计自由度

把参考稿当成设计词汇库，结合当前内容选用、混合或新建构图。分栏、虚线框、粗箭头、底部结论、章节页、进展标签和致谢均按用途选择；没有必要就省略。版式和章数不固定，字体与颜色遵循上述强制规则，参考稿不能覆盖。守住证据准确、演示可读与验收真实这三项底线，而不是复制模板。

## 开始工作

先读需求、现有稿和参考材料，确认听众、时长、交付格式、已有证据及本轮范围。能自行查明的先查；把影响结构或结论的缺口集中询问，继续不依赖回答的工作。用户只要求局部调整时，不重做已认可页面。

新稿先列逐页规划：本页问题或主判断、证据来源、图形形式、模块关系、讲述时间。若用户明确要求分阶段交付，按阶段交付；否则规划属于内部制作过程，继续完成 PPT。篇幅由内容和时间决定。

## 设计与制作

1. **组织叙事。** 新稿或重构时读 [叙事与讲稿](references/narrative.md)。根据长度和用途组合目录、章节入口、技术内容、总结及结束页；短报告或局部页面可省略导航与仪式性页面。章节入口用主标题和最简真实路线揭示本章要解决的问题。
2. **选择布局。** 新设计或重构时读 [布局与视觉语法](references/layouts.md)，按 [完整页面参考库](references/gallery.md) 的关系索引通常选2–4张相关页面，优先读可编辑PPT及其导出画面；无视觉能力时按 [参考文件使用说明](references/template-use.md) 读取逐页布局JSON。理解图证据、解释层和阅读顺序，再迁移到当前内容。图册提供37张完整页面及变形建议，不限定可用构图。先整合同一任务的互补证据，再按独立问题和阅读负荷决定分页；让方法、证据和结论占据不同层级，避免纯文字卡片堆叠或无解释的大图。
3. **主动寻找素材并安放证据。** 配图不足时，在获准的检索范围内自主查文献、找可复用的图片元素，按 [图件与证据](references/figures-evidence.md) 核对原图、图注及来源；不等用户逐张提供。默认采用现有科研素材；只有用户明确要求或明确批准后才能调用生图模型，具体授权边界见该指南。原生流程图和基于真实数据的绘图照常制作。研究结果、模型预测、文献示意和计划分别表述，图片承担解释任务，必要限定贴近相关主张。
4. **生成成品。** 制作或导出时读 [实现与验收](references/build-qa.md) 的首选工作流：环境支持时优先用 `@oai/artifact-tool` 的 JavaScript 接口生成可编辑PPT，Python辅助素材、核对和局部修改，再重新读取最终PPT渲染验收。局部修改保留用户的非目标内容。工具缺失时按该指南选替代，整页截图不能替代可编辑PPT，除非用户明确接受。
5. **配齐讲稿。** 用户未要求例外时，每页提供可直接讲述的备注，语言跟随汇报语言。备注写口头汇报正文，来源清单和制作说明另存；其余规则见叙事指南。

首次确立风格，先做少量覆盖主要页面类型的代表页，渲染后检查，再扩展整稿。已有认可稿时直接复用其视觉语法，不新增重复确认环节。代表页完成、收到反馈或交付前，按 [常见问题](references/common-problems.md) 检索适用条目并核对验收条件；不把全部修补做法叠加到每页。

## 验收与交付

交付前落实实现指南中的三项独立检查：**科学内容、实际画面、文件结构**。有演示生成库并不代表有渲染器；检测到缺失时只报告实际验证范围。

交付前必须运行两项检查，再按实现指南逐页复核全部小字和中英文混排。路径相对于本技能根目录；`python` 指可用的 Python 3：

```bash
python scripts/audit_pptx.py /path/to/deck.pptx --require-notes --output /path/to/audit.json
python scripts/audit_slide_rules.py /path/to/deck.pptx --output /path/to/slide-rules.json
```

结构检查和短语/字体检查不能替代语义与视觉审核；没有关键词命中不等于没有防御性说明。逐项处理报告发现的问题并检查实际画面，不能将未解析字体或图片内文字算作已通过。若当前Agent无视觉能力，按参考文件使用说明完成可执行检查并说明未完成的视觉验收。复核修改页及受影响的相邻页，整体风格首次建立或大规模改版时看全稿。新增图件、数据或换字体后检查其实际导出表现。

交付可编辑 PPT、所需预览及讲稿，保留复现所需源文件和来源索引。校验最终文件与已审阅版本一致。只在用户要求或覆盖前确有恢复需要时保留明确的恢复副本，不积累无意义版本。

## 环境与可移植性

核心规则采用通用 Markdown 和相对路径。Codex 可使用 `agents/openai.yaml` 的可选界面元数据；其他 Agent 直接读本文件。工具选择、缺少能力时的处理见实现指南，不依赖特定插件或本机路径。技能不授权安装、发布或上传研究材料。
