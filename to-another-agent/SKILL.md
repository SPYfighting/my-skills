# to-another-agent

以用户当前命令为准，不另建角色体系，也不根据风险、任务长度或完成状态升级流程。本技能负责规范读取顺序、项目记录和下一份提示词。

## 选择动作

- **接手当前项目**：读 `references/项目文件兼容.md` 和 `references/接手当前项目.md`。先完成项目工作，到完成、受阻或用户要求的停点时再整理现场。
- **交给下一位继续**：读 `references/项目文件兼容.md` 和 `references/继续交接.md`。
- **让下一位审查**：读 `references/项目文件兼容.md` 和 `references/提交审查.md`。
- **审查当前项目**，或接手有效的 `review-request` 文档：读 `references/执行审查.md`。
- **处理审查结果**：读 `references/项目文件兼容.md` 和 `references/处理审查结果.md`。

用户只说使用本技能而未说明动作时，按“交给下一位继续”处理。审查文档必须以 `协议` 和 `交接类型` 确认，文件名本身不决定路由。

## 可选规则

- 用户明确要求细粒度步骤和逐步核验时，另读 `references/细粒度任务.md`。
- 用户明确给出当前或下一位 agent 的工作结束时间时，另读 `references/时限与收尾.md`；项目交付日期只记入 task，不触发会话收尾。
- 发现仍在运行或等待结果的服务器、集群或后台任务时，另读 `references/remote-work.md`。

## 共用规范

1. 先读项目级指令和当前动作点名的文件；涉及 handoff 或 task 定位时按已加载的项目文件兼容规则读取事实源，以实际文件和可观察状态为准。
2. 更新项目已有事实源；只有审查请求和结果写入 `cross-agent-review-files/`。
3. 保留用户明确写出的范围、权限和操作限制，包括“不得修改”“先回报再处理”等否定式限制。
4. 活动服务器任务默认继续运行；不因交接停止、取消、重启或重复提交。记录接管所需状态，除非用户明确要求或安全条件必须停止。
5. 提示词保持运行时中立，只写应读文件、第一动作、明确限制和回报条件；独立核对写成职责，不指定执行机制。
6. 每次完成本技能后，把同一条简短提示词写入交接文档，并在回复末尾用 `text` 围栏代码块原样给出，便于直接复制。

接手提示词先要求读取文件并开展项目工作；只在完成、受阻或再次交接时使用本技能更新现场，避免接手后立即再次交接。

## 核验

新建或更新默认格式文档后运行：

```text
python <skill-dir>/scripts/check_relay.py <文档> --workspace <项目根目录> [--tasks <任务文件>]
```

`--tasks` 可以指向项目原生任务文件；此时校验器只核对凭据风险、文件存在性和 handoff 引用一致性，不要求改成技能模板。历史 v2 文档中的角色字段和旧文件名继续兼容读取，新文档不再生成这些字段。
