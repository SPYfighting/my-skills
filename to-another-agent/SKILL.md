# to-another-agent：把项目交给下一位 agent

交付的是可核验、可继续的项目现场，不是聊天摘要。下一位 agent 应能从落盘文件确认当前状态，先验收不确定现场，再继续任务或接管远程工作。

## 先确定当前角色

按实际授权和本轮工作识别角色，可同时具有多个角色，但分别陈述证据边界：

- **负责者**：记录实际完成、进行中、验证结果和未完成实现。
- **审核者**：记录审查范围、发现与未核实项，不把被审对象的工作写成自己已完成。
- **规划者**：记录目标、输入、方案与决策门槛；尚未执行的内容保持为计划。

## 整理现场

1. 找到项目根目录及项目级指令，盘点现有 handoff、task/todo、plan、result/report、验证记录和远程任务入口。已有约定优先，不创建重复事实源。
2. 从文件、版本控制状态、实际产物、验证命令及可观察的远程状态重建事实。把用户陈述、实际观察、验证结果、推断和未核实项区分开。
3. 更新相应事实源：
   - 结果与验证写回既有结果记录；只把有证据的事项标为完成。
   - 未完成工作写进既有 task/plan 文件，附具体动作、输入输出和完成判据。
   - 不确定或需要复核的结论写成“接手先验收”任务，说明现场、疑点、验收动作和通过条件。
   - handoff 只汇总当前现场并指向这些记录，不复制长内容。
4. 若项目没有合适载体，使用 `references/default-handoff.md` 的兼容式默认结构：根目录创建 `AGENT_HANDOFF.md`；存在后续工作时创建 `tasks/next-agent.md`。
5. 远程任务默认保留运行。读取 `references/remote-work.md`，记录下一位 agent 监控、接管和接收结果所需的最小事实。只有用户授权或任务本身明确要求时才停止进程。
6. 重读所有改动，核对路径、状态、命令、时间和完成判据。默认文件可运行：

   ```text
   python <skill-dir>/scripts/check_handoff.py --handoff <project>/AGENT_HANDOFF.md --tasks <project>/tasks/next-agent.md --workspace <project>
   ```

   项目已有格式时按其检查方式验证；不要为了通过本脚本改写成熟的项目约定。

交接准备不扩展当前权限。提交、推送、终止任务、移动数据或修改外部系统仍按原任务授权执行。

## 回复用户

简要报告已更新的文件、仍在运行的远程任务、首个待验收或待执行事项，以及未验证边界。最后给一条可直接发给下一位 agent 的提示词，包含实际交接文件和任务文件路径：

> 请使用 `$to-another-agent` 接手当前项目。先读取 <交接文件> 和 <任务文件>，优先验收“接手先验收”事项，再继续未完成任务；接管并监控其中记录的远程任务。

没有远程任务或独立任务文件时删去对应分句，不让提示词声称不存在的现场。
