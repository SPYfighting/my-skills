# to-another-agent：交接与审查闭环

交付可核验、可继续的现场。项目事实留在既有 handoff、task、plan 和结果记录中；只有独立审查证据进入 `cross-agent-review-files/`。Agent 由用户切换，本技能不自动创建 agent，也不扩大权限。

## 先选主路由

按顺序判断，命中即停：

1. 给出 `*-审查.md` 或要求处理审查反馈 → 读 `references/处理审查结果.md`。
2. 给出 `*-请求.md` 或要求执行审查 → 读 `references/执行审查.md`。
3. 明确要求审查，或完成产物含高后果判断、实质判断或未充分验证部分 → 读 `references/提交审查.md`。
4. 未完成工作、规划、远程任务，或低风险且充分验证的产物 → 读 `references/继续交接.md`。

只有工作是否已准备送审无法从现场判断、且选择会改变下一角色时才询问。

## 再叠加可选修饰器

- 用户明确要求“细粒度、逐步执行、供较弱模型接手”等同义要求时，另读 `references/细粒度任务.md`；没有明确要求就不加载、不套模板。
- 用户给出结束时间、截止时间或工作时限时，另读 `references/时限与收尾.md`。
- 存在仍在运行或等待结果的远程工作时，另读 `references/remote-work.md`。

## 共用协议

- 协议标记为 `to-another-agent/v2`；交接类型使用 `continue`、`review-request`、`review-result` 或 `address-findings`。
- 先核对文件、版本状态、实际产物、验证命令和可观察远程状态，再更新项目已有记录；缺少载体时才创建 `AGENT_HANDOFF.md` 与 `tasks/next-agent.md`。
- 区分实际验证、来源事实、用户陈述、假设、推断和未核实项；不把聊天摘要当项目事实源。
- 自主选择 `下一角色`：未处理审查发现→工作方；高风险完成产物或用户要求独立验收→审查方；到达收尾且远程任务仍运行→监控方；仍有可执行任务→执行方；只有规划工作→规划方；工作完成且证据齐全→验收方。
- 每次交接都在文档和回复中原样给出提示词。提示词点明角色、应读文件、第一动作、完成或回报触发条件、适用截止时间和远程状态；到触发条件时要求再次使用 `$to-another-agent` 更新现场。
- 即使工作已完成，也生成供未来使用的“验收或恢复”提示词；不表示必须立即启动新 agent。

## 机械核验

新建或更新默认格式文档后运行：

```text
python <skill-dir>/scripts/check_relay.py <文档> --workspace <项目根目录> [--tasks <任务文件>]
```

校验器自动识别 handoff、task、审查请求和审查结果。历史 v2 普通文档及旧审查文档保持兼容；handoff 或审查结果关联任务文件时传入 `--tasks`。

## 回复用户

简述更新的文件、交接类型、下一角色、首个待验收或待执行事项、远程状态和未验证边界。最后逐字给出文档中的下一位 agent 提示词；不存在的任务文件、截止时间、远程任务或复审要求不写入。
