# to-another-agent：交接与审查闭环

交付的是可核验、可继续的现场。项目事实留在既有 handoff、task、plan 和结果记录中；审查目录只保存审查证据。Agent 之间由用户复制提示词切换，本技能不自动创建 agent，也不扩展当前权限。

## 先选交接类型

按顺序判断，命中即停：

1. 用户给出 `*-审查.md` 或要求处理审查反馈 → **处理审查结果**。
2. 用户给出 `*-请求.md` 或要求执行审查 → **执行审查**。
3. 用户明确要求审查，或已完成的实质产物含高后果判断、未完全验证部分 → **提交审查**。
4. 未完成工作、规划、远程任务或低风险且已充分验证的产物 → **继续交接**。

只有工作是否已经准备送审无法从现场判断、且选择会改变下一位 agent 的角色时才询问用户。

## 四个分支

- **继续交接**：读 `references/继续交接.md`。更新现有事实源；没有载体时才创建默认文件。
- **提交审查**：读 `references/提交审查.md`。工作或规划 agent 写审查请求，并给 reviewer 提示词。
- **执行审查**：读 `references/执行审查.md`。reviewer 核对实际产物，只写审查结果，不修改被审产物、项目 task 或 handoff。
- **处理审查结果**：读 `references/处理审查结果.md`。工作 agent 将发现落实到 task，修正、验证并按需发起下一轮。

涉及仍在运行的远程工作时，分支 reference 之外再读 `references/remote-work.md`。

## 共用约束

- **现场优先**：文件、版本控制状态、实际产物和可复跑命令高于交接叙述。
- **单一事实源**：更新项目已有记录；交接文档使用路径和窄锚点引用，不复制长内容。
- **证据分级**：区分实际验证、来源事实、用户陈述、假设、推断和未核实项。
- **增量轮次**：`rN` 只覆盖本轮变化和上一轮未闭合发现，已经通过的部分不重审。
- **提示词落盘**：每份 v2 交接或审查文档都包含“下一位 agent 接手”，回复中原样提供。

## 机械核验

新建或更新本技能默认格式的文档后运行：

```text
python <skill-dir>/scripts/check_relay.py <文档> --workspace <项目根目录> [--tasks <任务文件>]
```

校验器自动识别 handoff、task、审查请求与审查结果。没有 `to-another-agent/v2` 标记的历史审查文档按旧规则检查并提示升级，不因缺少新字段而失败。项目已有成熟格式时沿用项目自己的检查方式。

## 回复用户

报告更新的文件、当前交接类型、远程任务状态、首个待验收或待执行事项和未验证边界。最后逐字给出文档中“下一位 agent 接手”的提示词；不存在的任务文件、远程任务或复审要求不写进提示词。
