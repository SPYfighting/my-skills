# 细粒度任务

仅在用户明确要求逐步操作和逐步核验时使用。普通交接不加载本文件。

在项目职责对应的既有 task 文件中加入以下信息；保留项目原有目录、命名和状态表分工，不另建一套细粒度任务。项目原生格式不使用这些字段名时，可用等价栏目表达，但信息不能缺失：

```markdown
- 任务粒度：fine
- 执行策略：persistent
```

每个任务写目标、输入、输出、总完成判据和回报节点；每一步只包含一个可观察动作：

```markdown
- [ ] T1 <具体任务>
  - 目标：<单一结果>
  - 输入：<文件、数据和前置条件>
  - 输出：<明确产物>
  - 完成判据：<客观终态>
  - 默认回退：<用户或项目已经允许的回退；没有则写“无”>
  - 回报节点：S2
  - 执行步骤：
    1. [ ] S1 <单一动作>
       - 操作：<路径、命令、参数或编辑对象>
       - 核验：<实际检查>
       - 通过条件：<客观结果>
       - 未通过动作：<修复并重验；何种情况才暂停交接>
       - 证据：待执行
```

只冻结已经确定的路线。用户留给下一位判断的选择写成决策步骤，列出输入证据、选择标准和允许分支，不替用户预先决定，也不创造未授权回退。

步骤通过后继续下一步；可修复失败先修复并重验。完成里程碑、全部完成、实质受阻或留下活动服务器任务时，更新步骤证据和 `执行回报`。用户明确设置 agent 工作结束时间时，再增加收尾回报。

```markdown
## 执行回报

### R1
- 时间：<带时区时间>
- 状态：milestone / complete / blocked / deadline-handoff / remote-running
- 完成步骤：<步骤编号>
- 关键结果：<结果>
- 核验证据：<锚点、产物或命令结果>
- 剩余事项：<下一步或无>
```
