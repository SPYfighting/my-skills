# 提交审查

适用于工作或规划 agent 把已经准备交付的产物交给一个不了解本轮对话的 reviewer。请求的目标是帮助 reviewer 找出错误，不是证明提交方正确。

## 步骤

1. **定范围**：写明用户要求审查的范围；未指定时取本轮完成的实质工作。范围外的既有内容不归入发现。
2. **取原话**：逐字摘录用户需求及后续修订。无法恢复原话时如实写“未能恢复”，并指向生效的 spec 或 task，不自行补写。
3. **列交付物**：每项写路径、用途和状态；部分完成、未做和计划项同样列出。
4. **写关键决策**：只列换一个选择会明显改变交付的决定，写明备选、理由和窄锚点。
5. **标证据等级**：实际验证过、来源事实、用户陈述、假设、推断。
6. **列验证边界**：分别写已验证、未验证及原因。
7. **排最不确定处**：至少一条，按错误后果排序，说明错了会怎样。
8. **声明范围外**：写清未做事项及原因。
9. **选择轮次**：首轮为 `r1`；后续轮次只列上一轮之后的变更和未闭合发现。
10. **落盘并核验**：写入 `cross-agent-review-files/<YYYY-MM-DD>-<任务简称>-r<轮次>-请求.md`，运行 `check_relay.py`。

## 完成判据

- 每项交付物带路径；关键决策和不确定处带窄锚点或可复跑命令。
- 至少一条最不确定处。
- `rN`（N > 1）逐条列出本轮变更和上一轮未闭合发现，并指向同一任务的 `rN-1` 结果；轮次从 `r1` 开始。
- 文档内的提示词包含自身文件路径，可直接复制给 reviewer。
- 统一校验器通过。
