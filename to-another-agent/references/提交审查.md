# 交给下一位审查

仅在用户要求下一位 agent 审查时创建请求。请求写入 `cross-agent-review-files/<YYYY-MM-DD>-<任务简称>-r<轮次>-请求.md`；审查目录只保存审查证据，不替代项目 task、handoff 或结果记录。

请求应当让不了解当前对话的 reviewer 能直接读取实际产物：

1. 原样保留用户的审查要求和范围。
2. 列出交付物路径、状态、已验证和未验证部分。
3. 只记录实际存在的关键决策；没有则写“无实质决策”。
4. 列出最不确定处及锚点或可复跑命令。
5. 多轮审查只写本轮变化和上一轮未闭合发现。
6. 生成简短 reviewer 提示词并运行校验器。

## 请求模板

````markdown
# 审查请求：<任务简称> r<轮次>

- 协议：to-another-agent/v2
- 交接类型：review-request
- 日期：<YYYY-MM-DD>
- 工作区：<绝对路径>
- 范围：<审查边界>
- 分支 / commit：<如有>
- 任务文件：`<项目现有任务文件>` / 无
- 上一轮：`<上一轮结果>` / 无

## 0. 本轮范围

<本轮交付，或相对上一轮的变化和未闭合发现>

## 1. 用户原始需求（逐字引用）

> <用户要求>

## 2. 交付物

| 路径 | 说明 | 状态 |
|---|---|---|
| `<path>` | <用途> | 完成 / 部分完成 / 未做 |

## 3. 关键决策

无实质决策。

## 4. 判断依据与证据等级

| 依据 | 性质 | 出处或验证方式 |
|---|---|---|
| <主张> | 实际验证 / 来源事实 / 用户陈述 / 假设 / 推断 | <证据> |

## 5. 已验证与未验证

**已验证**
- <检查及结果>

**未验证**
- <对象和原因> / 无

## 6. 最不确定处

1. **<问题>** —— 锚点：`path/to/file:12-20`
   如果这里错了：<影响>

## 7. 明确不在范围内

- <事项和原因> / 无

## 8. 下一位 agent 接手

```text
请读取 `cross-agent-review-files/<本文件名>` 及其中列出的实际产物，按请求范围完成只读审查，并把结果写入同轮审查结果文件。完成或实质受阻时，使用 `to-another-agent` 技能整理审查结果和下一份提示词。
```
````

提示词保持运行时中立。任务路径按项目规则、handoff 和任务索引定位；项目已有 task/plan 或状态表时引用实际入口，不创建平行任务文件。
