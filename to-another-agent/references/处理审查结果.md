# 处理审查结果

适用于工作或规划 agent 接回 reviewer 的结果。审查结果同样是一组需要核对的主张；先确认它对应正确请求和实际现场，再执行修正。

## 步骤

1. 对结果文档运行 `check_relay.py`，读取对应请求、结论、发现、未能核实项和上一轮状态。
2. 确认当前产物仍与被审版本一致；若审查后已有其他修改，先区分哪些发现仍适用。
3. 将每条阻断和重要发现落实到项目现有 task 文件：
   - 任务标题记录带轮次的完整发现编号（如 `r1-F1`），正文写证据位置、拟采取动作和完成判据。
   - 不在聊天中维护另一份待办清单。
   - 使用本技能默认 task 格式时，将 `交接类型` 更新为 `address-findings`；全部闭合后改回 `continue`。
   - 落实后运行 `check_relay.py <审查结果> --workspace <根目录> --tasks <任务文件>`，确认每条阻断和重要发现都有任务条目。
4. 对每条发现记录处理状态：
   - **已修正**：附改动锚点和验证结果。
   - **接受风险**：写明用户授权或依据。
   - **延期**：写明任务位置和解锁条件。
   - **拒绝**：用现场证据说明发现为何不成立。
   - **范围外**：引用用户要求或有效范围边界。
5. 在当前权限内修正并运行相称验证。审查建议不自动扩大修改、提交、推送或外部操作权限。
6. 需要复审时读取 `references/提交审查.md`，创建 `rN+1` 请求，只列本轮变化和上一轮未闭合发现。
7. 审查通过或所有要求已闭合时，更新最终 handoff、结果记录和任务状态，生成普通继续交接或结束提示词。
8. 未闭合发现存在时下一角色为工作方；修正后需独立复审时切换为审查方；全部闭合且证据齐全时切换为验收方。提示词写明处理或验收完成后再次使用 `$to-another-agent` 回报。

## 何时必须复审

- 修正了阻断发现。
- 重要发现的修正改变了实质行为、科研结论、关键数据或交付结构。
- reviewer 标记为“存疑”的阻断或重要问题已经获得新证据。

纯文字校正或明确延期的可选项不强制复审，但处理状态必须落盘。

## 下一轮请求

`rN+1` 的“本轮范围”必须逐条回应上一轮发现：

| 上一轮编号 | 处理状态 | 本轮证据 |
|---|---|---|
| r1-F1 | 已修正 / 接受风险 / 延期 / 拒绝 / 范围外 | `path/to/file:12-40` 或验证命令 |

上一轮已经确认通过的部分不重复送审。

## 完成判据

- 阻断和重要发现全部进入项目 task 或有已验证的闭合状态。
- 每项修正有改动证据和验证结果。
- 需要复审时已经创建并验证下一轮请求。
- 无需复审时，最终 handoff、结果和任务记录已经更新。
- 回复中的下一位 agent 提示词与落盘文档完全一致。
