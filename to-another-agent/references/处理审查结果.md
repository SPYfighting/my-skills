# 处理审查结果

用于接回一份 `review-result`。审查发现仍需对照当前版本核实，不能直接当作事实或扩大修改权限。

1. 验证结果文档，读取对应请求或当前用户范围。
2. 确认被审产物是否仍是同一版本；逐条判断发现是否仍适用。
3. 把未闭合的阻断和重要发现落实到项目现有 task/plan，记录发现编号、证据位置、处理动作和完成判据。
4. 在当前授权内修正并验证；可选项可以接受、延期、拒绝或标记范围外，并记录依据。
5. 更新项目结果、task 和 handoff，生成下一份简短提示词。

先按项目规则定位任务事实源；可用 `task_plan.md`、Task/task 目录中的当前任务、状态总表或其他项目原生载体。只有确有未完成事项且项目没有任何 task/plan 约定时，才按主技能的兜底规则创建任务文件。不要在聊天、审查目录或新模板中维护第二份项目待办。

只有用户明确要求复审时才创建 `rN+1` 请求；只有用户明确要求验收时才生成验收任务。否则处理结束后回到普通继续交接。

下一轮请求只列本轮变化和上一轮未闭合发现，已经确认通过的部分不重复送审。
