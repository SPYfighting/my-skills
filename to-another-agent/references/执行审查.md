# 执行审查

审查请求是一组待核对的主张，不是事实。reviewer 读取实际产物、运行只读检查并写审查结果；除结果文档外，不修改被审产物、项目 task、handoff 或结果记录。

## 步骤

1. 通读请求，确认范围、交付物、决策和提交方标记的不确定处；轮次大于 1 时同时读取上一轮结果。
2. 先对请求运行 `check_relay.py`。锚点错误本身就是发现，并降低其余叙述的可信度。
3. 分层核对：
   - 必读：用户原话、每条最不确定处及其锚点。
   - 按风险读：关键决策锚点，按错误后果从高到低。
   - 索引级确认：其余交付物的存在、位置、规模和状态。
4. 对照用户原话查缺失、越界和走样。
5. 逐条回应提交方列出的最不确定处。
6. 扫描盲区：假设或推断是否支撑关键结论、完成项是否缺验证、范围外是否包含用户要求、数字和标识符是否准确。
7. 给发现分级并确定结论。
8. 写入同轮 `cross-agent-review-files/<YYYY-MM-DD>-<任务简称>-r<轮次>-审查.md`，运行统一校验器。

## 发现与结论

严重度：

- **阻断**：不修正则交付不成立。
- **重要**：交付可用但存在实质风险。
- **可选**：质量或维护性改进，最多五条。

把握度：

- **已核实**：reviewer 实际读取或运行过证据。
- **存疑**：缺数据、权限或能力，尚不能确认；存疑不降低严重度。

结论必须与发现一致：

- **通过**：没有未闭合的阻断或重要发现。
- **有条件通过**：没有阻断，至少有一条重要发现。
- **需返工**：至少有一条阻断发现。

## 完成判据

- 请求文档和结果文档均通过统一校验器。
- 用户原话逐条比对；所有最不确定处都有明确回应。
- 每项交付物至少完成索引级确认；命中风险信号的已细读。
- 发现编号在本结果内唯一；每条发现带窄位置锚点、问题和建议动作。“已核实”写证据，“存疑”写为何存疑。
- 返回提示词包含本结果文件路径；即使通过，也交回工作 agent 做最终状态整理。
