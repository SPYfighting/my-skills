# 默认交接结构

仅在项目没有可复用的 handoff、task、todo、plan 或结果记录约定时使用。字段可以按项目删减，但事实类型和接手入口必须保留。

## `AGENT_HANDOFF.md`

```markdown
# 项目交接

- 更新时间：YYYY-MM-DD HH:MM +时区
- 当前角色：负责者 / 审核者 / 规划者
- 当前目标：一句话说明本次交接所服务的目标
- 状态基线：分支、提交或其他可复现版本；非版本库写“无版本控制”
- 后续任务：`tasks/next-agent.md` / 无

## 项目现场

当前阶段、关键入口、工作目录和能直接继续工作的最小背景。

## 已完成与证据

- 事项；证据为 `path/to/file:line`、产物路径或可复跑命令。

## 进行中工作

- 当前停点、已产生的中间产物、下一安全动作；没有则写“无”。

## 结果与验证

- 实际运行的命令、时间、结果和未覆盖范围。引用既有结果记录，避免复制整份内容。

## 远程任务

无活动远程任务。

## 决策、边界与风险

- 已确定的选择及理由。
- 用户授权或项目范围边界。
- 推断、未核实信息和可能影响后续结论的风险。

## 接手入口

1. 先核对状态基线和工作区改动。
2. 验收 `tasks/next-agent.md` 中的“接手先验收”事项。
3. 从最高优先级未完成任务继续。
```

## `tasks/next-agent.md`

每个未完成项都必须有完成判据；不确定现场还要有验收动作。

```markdown
# 下一位 agent 任务

## 接手先验收

- [ ] T1 核验具体结论或现场
  - 现场：文件、结果、日志或远程任务位置
  - 疑点：为何当前不能确认
  - 验收动作：下一位 agent 应实际检查什么
  - 完成判据：什么证据足以确认、否定或升级处理

## 待执行

- [ ] T2 完成具体工作
  - 输入：所需文件、数据或前置条件
  - 输出：明确产物
  - 完成判据：可观察的通过条件

## 受阻

- [ ] T3 等待外部条件或用户决定
  - 阻塞条件：当前缺少什么
  - 解锁条件：出现什么状态后可以继续
  - 完成判据：阻塞被解除并更新到“待执行”或完成
```

任务编号只需在当前文件中唯一。项目已有任务标识时沿用原标识。

## 与既有文件的关系

- 既有结果记录保存结果细节；handoff 只写结论、验证状态和链接。
- 既有 task/plan 文件保存后续动作；handoff 只指出第一入口。
- 既有审查文档保存发现；handoff 说明哪些发现已闭合、哪些需要下一位 agent 验收。
- 同一事实只维护一处，其他文件使用路径和窄锚点引用。
