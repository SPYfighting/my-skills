# 项目文件兼容

用于定位项目已经采用的 handoff、task/plan、状态表和结果记录，避免本技能产生第二套事实源。

## 定位顺序

1. 用户点名的路径。
2. 项目级指令或入口文档声明的当前路径。
3. 当前 handoff、任务索引或状态表链接的路径。
4. 项目根目录及现有 `Task/`、`task/`、`tasks/` 目录中的活动文件。

`archive`、`历史`、`归档`、`留档`、`backup`、`snapshot` 和版本快照中的副本不作为当前入口，除非项目规则明确指向它。多个候选并存时，以项目声明和相互链接关系确定职责；不要按文件修改时间猜测。

## 写入规则

- 沿用现有文件名、目录、职责分工和原生格式，不新建等效 handoff 或任务清单。
- 项目有状态总表、阶段计划和具体 Task 时，只更新职责覆盖本次变化的文件；handoff 指向下一位实际先读的具体入口。
- 在现有 handoff 中更新可复制提示词；协议字段只在文件已经采用 relay 协议或项目格式允许时补充，不用技能模板整体重写项目原生文档。
- `cross-agent-review-files/` 只保存独立审查请求和结果，不保存项目任务或普通 handoff。

## 没有既有约定时

- handoff 兜底为项目根目录 `HANDOFF.md`。
- 只有确有未完成工作且没有 task/plan 载体时才建任务文件：优先沿用已有 `Task/` 或 `tasks/` 的命名习惯；两者都不存在时使用 `tasks/next-agent.md`。
- 项目已完成时可以只建 handoff，不为“未来可能有任务”创建空任务文件。
