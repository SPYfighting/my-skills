# 继续交接

用于把当前项目交给下一位 agent 继续。当前 agent 只整理真实现场、更新项目记录并生成提示词，不替下一位执行后续任务。

## 整理顺序

1. 找到项目级指令和现有 handoff、task/plan、result/report、验证记录。
2. 核对版本状态、实际产物、首个未完成任务和可观察的服务器任务状态。
3. 把结果与验证写回既有结果记录，把未完成工作写回既有 task/plan，handoff 只保留接手所需摘要和文件入口。
4. 只有会阻碍安全继续的不确定现场才写入“接手先核对”，并给出最小核对动作。
5. 没有合适载体时才使用下面的默认文件。

## 默认 `AGENT_HANDOFF.md`

````markdown
# 项目交接

- 协议：to-another-agent/v2
- 交接类型：continue
- 更新时间：YYYY-MM-DD HH:MM +时区
- 当前目标：<项目目标>
- 状态基线：<分支、commit 或无版本控制>
- 后续任务：`tasks/next-agent.md` / 无

## 项目现场

<当前阶段、关键入口和首个待办所需背景>

## 已完成与证据

- <事项>；证据：<路径、产物或可复跑命令>

## 进行中工作

- <当前停点、已有中间产物和下一安全动作> / 无

## 结果与验证

- <实际运行的检查、结果和未覆盖范围>

## 远程任务

无活动远程任务。

## 决策、边界与风险

- <仍然生效的用户要求、权限限制、已定决策和未核实边界>

## 接手入口

1. 读取本文件和后续任务文件。
2. 核对状态基线、当前改动、关键输入和首个待办。
3. 达到可安全继续的边界后推进未完成工作。

## 下一位 agent 接手

```text
请读取 `AGENT_HANDOFF.md` 和 `tasks/next-agent.md`，核对当前现场后继续最高优先级未完成任务，并保持其中记录的服务器任务运行。完成、实质受阻或需要再次换手时，使用 `to-another-agent` 技能更新项目记录并生成下一份接手提示词。
```
````

按现场删除不存在的任务文件或服务器任务分句。用户的只读、等待确认、禁止操作等限制必须进入提示词。

## 默认 `tasks/next-agent.md`

```markdown
# 下一位 agent 任务

- 协议：to-another-agent/v2
- 交接类型：continue

## 接手先核对

- [ ] T1 <仅影响安全继续的不确定现场>
  - 现场：<文件、日志或结果位置>
  - 核对动作：<最小检查>
  - 完成判据：<什么证据足以继续>

## 待执行

- [ ] T2 <具体任务>
  - 输入：<文件、数据或前置条件>
  - 输出：<明确产物>
  - 完成判据：<可观察终态>

## 受阻

- [ ] T3 <受阻事项>
  - 阻塞条件：<缺少什么>
  - 解锁条件：<何时可继续>
  - 完成判据：<如何确认解除>
```

项目已经完成时可以没有 task 文件，但仍留下简短恢复提示词：

```text
请读取 `AGENT_HANDOFF.md`，核对当前完成状态和未验证边界；有新任务时从这里恢复。状态发生变化或需要再次交接时，使用 `to-another-agent` 技能更新记录并生成新的接手提示词。
```
