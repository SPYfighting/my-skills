# 继续交接

用于把当前项目交给下一位 agent 继续。当前 agent 只整理真实现场、更新项目记录并生成提示词，不替下一位执行后续任务。

## 整理顺序

1. 先按 `项目文件兼容.md` 读取项目级指令、当前 handoff、task/plan、状态表、result/report 和验证记录。
2. 核对版本状态、实际产物、首个未完成任务和可观察的服务器任务状态。
3. 把结果与验证写回项目指定的结果记录，把未完成工作写回职责对应的 task/plan 或状态表；handoff 只保留接手所需摘要和实际文件入口。
4. 只有会阻碍安全继续的不确定现场才写入“接手先核对”，并给出最小核对动作。
5. 在项目原生 handoff 中加入或更新“下一位 agent 接手”提示词；保留其既有结构和命名，不复制成另一个 handoff。

如果多个 task 文件各有职责，例如总表记录状态、`task_plan.md` 记录当前阶段、具体 Task 记录操作步骤，则分别更新受本次变化影响的字段；不要选一个模板覆盖其他文件。handoff 的“后续任务”指向下一位真正应先读的具体入口。

## 没有项目约定时的兜底 handoff

仅在项目规则、入口文档和现有文件都没有 handoff 约定时，创建根目录 `HANDOFF.md`：

````markdown
# 项目交接

- 协议：to-another-agent/v2
- 交接类型：continue
- 更新时间：YYYY-MM-DD HH:MM +时区
- 当前目标：<项目目标>
- 状态基线：<分支、commit 或无版本控制>
- 后续任务：`<实际任务文件>` / 无

## 项目现场

<当前阶段、关键入口和首个待办所需背景>

## 已完成与证据

- <事项>；证据：<路径、产物或可复跑命令>

## 进行中工作

- <当前停点、已有中间产物和下一安全动作> / 无

## 结果与验证

- <实际运行的检查、结果和未覆盖范围>

## 远程任务

无活动远程任务。

## 决策、边界与风险

- <仍然生效的用户要求、权限限制、已定决策和未核实边界>

## 接手入口

1. 读取本文件和实际任务入口。
2. 核对状态基线、当前改动、关键输入和首个待办。
3. 达到可安全继续的边界后推进未完成工作。

## 下一位 agent 接手

```text
请读取 `HANDOFF.md` 和 `<实际任务文件>`，核对当前现场后继续最高优先级未完成任务。完成、实质受阻或需要再次换手时，使用 `to-another-agent` 技能更新项目原有记录并生成下一份接手提示词。
```
````

提示词必须替换为实际路径。没有任务文件时删除相应分句；有活动服务器任务时加入保持运行和接管监控的要求，没有时不要加入。用户的只读、等待确认、禁止操作等限制必须进入提示词。

## 没有项目任务载体时的兜底

项目已有 `task_plan.md`、任务状态表、Task/task 目录中的当前任务或其他任务系统时，直接更新它们，不使用本节。确有未完成工作但没有任务载体时：

- 已有 `Task/` 或 `tasks/` 目录：沿用其大小写、语言和命名习惯创建一个当前任务文件。
- 两者都不存在：创建 `tasks/next-agent.md`，使用下面的最小格式。

```markdown
# 下一位 agent 任务

- 协议：to-another-agent/v2
- 交接类型：continue

## 接手先核对

- [ ] T1 <仅影响安全继续的不确定现场>
  - 现场：<文件、日志或结果位置>
  - 核对动作：<最小检查>
  - 完成判据：<什么证据足以继续>

## 待执行

- [ ] T2 <具体任务>
  - 输入：<文件、数据或前置条件>
  - 输出：<明确产物>
  - 完成判据：<可观察终态>

## 受阻

- [ ] T3 <受阻事项>
  - 阻塞条件：<缺少什么>
  - 解锁条件：<何时可继续>
  - 完成判据：<如何确认解除>
```

项目已经完成时可以没有 task 文件，但仍在实际 handoff 中留下简短恢复提示词：

```text
请读取 `<实际 handoff 路径>`，核对当前完成状态和未验证边界；有新任务时从这里恢复。状态发生变化或需要再次交接时，使用 `to-another-agent` 技能更新项目原有记录并生成新的接手提示词。
```
