# 时限与收尾

用户指定结束时间、截止时间或工作时限时使用。目标是在期限前留下完整可接管现场；期限不是强杀远程进程或牺牲证据的理由。

## 计算时间

1. 把相对时限换算为项目或环境时区下的绝对时间，使用 ISO 8601 和数字时区，例如 `2026-11-11T18:00:00+08:00`。只有时区无法从用户、项目或环境确定时才询问。
2. 记录接手时间、结束时间、收尾开始和策略：

```markdown
- 接手时间：2026-11-11T12:00:00+08:00
- 结束时间：2026-11-11T13:00:00+08:00
- 收尾开始：2026-11-11T12:48:00+08:00
- 收尾策略：auto
```

用户明确指定收尾时间或预留时长时使用 `user-specified`。否则：

```text
预留分钟 = ceil(剩余窗口分钟 × 20%)，限制在 10–30 分钟
收尾开始 = 结束时间 - 预留分钟
剩余窗口不足 10 分钟时，收尾开始 = 接手时间
```

同一时间同步写入 task 与 handoff。时限只改变调度和收尾，不改变下一角色。

## 调度规则

- 接手时和开始每个步骤前重新核对当前时间。细粒度 task 的每一步必须写 `预计耗时`。
- 预计无法在收尾开始前完成的步骤不启动；优先完成能形成可验证里程碑的原子动作。
- 收尾开始前持续推进，不为普通中间通过条件停下会话。
- 到达收尾开始后，完成当前可安全结束的原子动作；不再启动新的编辑、提交、重跑或高成本计算。
- 随即更新步骤证据、`执行回报`、handoff、结果记录和下一提示词。状态使用 `deadline-handoff`；仍有远程任务时可使用 `remote-running`。

## 远程任务

活动远程任务默认继续运行，按 `references/remote-work.md` 记录任务 ID、当前状态、日志、监控方式、接管动作和停止条件。除非已有授权和安全条件明确要求，不因本会话时限停止或强杀进程。

到达收尾且远程任务仍运行时，在提示词写明结束时间、远程状态、第一项只读检查和回报条件；只有用户明确要求“监控、盯住、等待并接收结果”等意图时才改为监控方，否则保持接续方。

## 设计依据

只吸收公开流程原则，不复制其实现或模板：

- [handoff-now](https://github.com/talal-ai/handoff-now)（Apache-2.0）：在安全生命周期边界停止新风险动作，不强杀活动命令。
- [robbin/agent-relay](https://github.com/robbin/agent-relay)（MIT）：任务、状态和回执职责分开；本技能仍使用项目既有文件承载。
- [team-collab-skills](https://github.com/dadwadw233/team-collab-skills)（Apache-2.0 / CC-BY-SA-4.0）：入口只路由，checkpoint 细节按需加载。
