# 生物科研微信公众号写作

把论文、技术、代码仓库、实验记录或已有草稿转成专业、清晰、可追溯的微信公众号文章。默认读者是具备基础分子生物学知识的研究生、科研人员和产业研发人员；计算概念首次出现时，用一句话说明它在实际研究中解决什么问题。

交付目标是原创、发布就绪且证据可追溯的科研文章。围绕读者需要做出的判断或完成的任务组织内容，用 Figure、表格、代码或错误记录承担证据作用，并保持独立编辑判断。

## 选择级别并加载规则

先按读者读完后需要完成的任务选择级别；用户明确指定短文或长文时服从用户。

- **快评**：读者需要迅速判断一篇新论文、预印本、模型、工具或技术更新是否值得关注。读取 `references/short-commentary.md`。
- **深解**：读者需要读懂方法与关键图、开始使用工具、复现流程、诊断失败或系统了解一个领域。读取 `references/teaching-deep-dive.md`。
- **已有草稿**：用户提供草稿并要求修改时，再读取 `references/editing-existing-drafts.md`；仍按最终文章目的选择快评或深解。

新写文章时读取 `references/editorial-principles.md`。所有完整文章均读取：

1. `references/evidence-and-figures.md`
2. `references/wechat-layout-and-delivery.md`
3. `references/quality-gates.md`

只做标题、大纲或局部修改时，读取与该局部直接相关的文件，不生成完整发布包。

## 公共流程

### 1. 固定任务边界

记录目标读者、级别、主题、材料覆盖范围、用户是否授权第一人称，以及交付目录。只有缺失信息会改变结论、公开边界或文章级别时才询问用户；其余采用本技能默认值。

完成条件：能用一句话说明“这篇文章帮助哪类读者做出什么判断或完成什么任务”。

### 2. 盘点材料

优先使用用户提供的论文全文、补充材料、数据、代码和图片。涉及当前论文、模型版本、工具能力、团队信息、价格或日期时，核对当前一手来源。把材料覆盖范围标为：

- 全文与补充材料齐全
- 仅全文
- 仅摘要、项目页或二手材料
- 用户内部材料

只有摘要时，按有限证据写作；正文明确材料边界，不暗示完成了全文解读。

完成条件：所有将进入标题、摘要和核心结论的数字、日期、名称和状态都有实际来源位置。

### 3. 建立证据骨架

先写来源地图和关键主张清单，再写正文。为每个核心判断记录来源位置、证据身份、限制和允许的措辞强度。将模型预测、计算评分、实验结果和编辑判断分开。

完成条件：每个正文小节至少对应一个有来源的关键判断，或明确标为作者分析。

### 4. 选择主线与 Figure

围绕一个中心问题选择必要 Figure、表格、代码或错误记录。Figure 必须承担解释或证据作用；装饰图不占用正文位置。能合法获得论文原图时优先使用，许可不明确时放入资料参考区并制作原创解释图。

完成条件：每个拟用素材都已记录“放在哪里、说明什么、不能说明什么、是否可发布”。

### 5. 先写 Markdown 正文

按所选级别写 `公众号文章.md`。标题与开头从来源身份、核心动作、最具区分度的结果和必要限定中组合，不套固定句式。每个小标题承担一个判断，证据紧邻解释。

使用与证据强度匹配的语言。把预印本写成预印本，把相关性写成相关性，把结构预测写成结构线索，把模型得分写成模型得分。

完成条件：删掉任何一个小节都会造成主线或证据缺口；否则删除该小节。

### 6. 生成发布包

按 `references/wechat-layout-and-delivery.md` 生成 Markdown 主文件、同名预览 HTML、`imgs/cover.png`、正文图片和作者工作文件。普通来源链接保留为 Markdown 链接，交给发布技能转换为文末引文。

完成条件：所有必需文件存在，Frontmatter 完整，Markdown 中每个本地图片路径可读，封面存在且版权状态明确。

### 7. 过质量门

按 `references/quality-gates.md` 检查科学边界、原创性、结构、教学价值、版权和发布兼容性。运行 `scripts/validate_package.py`。若运行环境提供用户选定的微信发布适配器，再读取该适配器的当前说明并执行不创建草稿的 dry-run。

完成条件：验证器退出码为 0；无法执行的检查在 `发布前检查.md` 中说明原因和剩余风险。

## 权限边界

- 使用公开材料和用户文件做分析，不复制无授权公众号文章进入产物或技能资源。
- 不编造实验经历、未公开数据、作者关系、参数、统计量或代码运行结果。
- 不绕过付费墙、反爬验证、访问限制或图片许可。
- 只在用户明确要求发布时调用发布技能。生成发布包不等于发布成功。

## 默认交付

完整任务默认交付一个自包含目录，并在回复中说明：文章级别、主要来源、实际生成文件、验证结果、未确定项，以及下一步应把哪个 Markdown 文件交给用户选定的微信发布适配器。
