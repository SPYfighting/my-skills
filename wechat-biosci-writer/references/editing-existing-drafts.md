# 修改已有草稿

先确认用户要求的是校对、局部修订、结构重组还是重写。用户没有明确授权重写时，默认做能解决问题的最小修改，并保留原主线、作者声音和第一人称边界。

## 修改强度

- **校对**：改正事实、术语、语法、标点、链接和图片路径；不改变论证顺序。
- **局部修订**：修复薄弱段落、标题、摘要、图注或过强结论；相邻内容只作必要衔接。
- **结构重组**：重新排列小节、合并重复内容、补齐证据骨架；须在交付说明列出主要结构变化。
- **重写**：重新建立主线和表达。只有用户明确授权，或原稿无法通过科学边界且用户接受重写时执行。

用户说“润色”时按局部修订处理，不自动更换观点、删去重要限定或加入营销化结论。

## 编辑流程

1. 保存一份只读原稿或可比较的原始版本。
2. 按快评或深解规则判断原稿目标是否一致；不要仅因篇幅改变级别。
3. 建立问题清单，区分事实错误、证据缺口、逻辑断裂、读者障碍和纯风格问题。
4. 先修事实与证据，再修结构，最后修语言与移动端排版。
5. 新增事实、数字、图片和链接均进入 `资料与证据.md`；原稿中的无来源强结论应核验、降级或删除。
6. 在 `发布前检查.md` 记录修改强度、主要结构变化、保留的争议点和无法核实的内容。

## 作者声音与第一人称

- 不把 Agent 的检索、运行或判断伪装成作者亲历。
- “我们发现”“我们测试”等第一人称研究陈述，只有用户原稿已有且其身份清楚，或用户明确授权时保留或新增。
- 可保留确有信息价值的个人判断，但必须与来源事实分开。
- 不机械去除个性化表达；只删除空泛感叹、重复铺垫和会误导证据强度的夸张。

## 交付

用户只要求局部修改时，交付修改后的对应文件和简短变更说明。用户要求发布就绪文章时，仍须生成完整发布包，并用修改后的 `公众号文章.md` 作为默认发布入口。
