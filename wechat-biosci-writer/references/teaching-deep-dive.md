# 深解模式

## 目标

让读者能够理解关键方法与证据、判断适用范围，并开始实践、复现或设计下一步验证。论文深解通常为 4,500–8,000 个中文字符；教程、领域盘点和完整复现记录由教学闭环决定，不设机械上限。

深解不是扩写快评。先确定读者最终应获得的能力，再选择材料。

## 公共教学闭环

每个深解任务都覆盖：

1. 前置问题与成功判据
2. 输入、输出和关键约束
3. 方法或工作流的决策逻辑
4. 关键证据、对照或实际输出
5. 失败模式与诊断信号
6. 可复现程度与缺失信息
7. 适用范围、局限和下一步

第一次出现跨学科概念时，用“中文名 + 英文名 + 实际作用”解释。默认不讲读者已经具备的基础分子生物学常识。

## 分支一：论文教学级拆解

### 取材顺序

1. 用摘要定位作者声称解决的问题，不把摘要当结果证据。
2. 先读讨论与局限，确定作者承认的边界。
3. 选择 2–6 组承担主线的正文或补充 Figure。
4. 回到方法核对数据、模型输入输出、实验体系、重复、统计和评价指标。
5. 用补充材料查阈值、额外对照、失败结果和筛选细节。
6. 查代码、数据与利益冲突，判断可复现性和产业关联。

### 文章结构

- 用具体难点或关键结果说明为什么值得读。
- 给出核心贡献地图，避免逐节翻译论文。
- 解释方法中的关键设计选择及其理由。
- 按证据链讲结果：计算设计 → 生物物理或结构验证 → 功能 → 更高层级验证。
- 把筛选漏斗、版本迭代或基线比较整理成表格。
- 单列论文没有证明什么，以及哪些步骤无法由公开材料还原。
- 总结意义、主要不足和后续验证；区分作者提出与本文推断。

### Figure 单元

每组 Figure 使用以下顺序：

1. 一句话提出该图回答的问题。
2. 指定需要看的面板、轴、颜色或结构区域。
3. 报告实际观察和关键数值。
4. 说明对照、样本量或统计条件。
5. 给出允许的结论和剩余替代解释。

## 分支二：工具或复现教程

先确认实际版本、官方安装方式、许可、硬件或数据要求和输出格式。能够运行时先用最小真实输入验证，再写教程；不能运行时明确写成“基于文档的使用指南”。

教程至少包含：

- 任务定义与适用条件
- 环境和版本矩阵
- 输入文件、字段和示例
- 最小可运行流程
- 参数按决策场景解释，而不是复制 `--help`
- 输出目录和关键文件说明
- 成功信号、失败信号和排错顺序
- 结果如何接入下一步分析或实验
- 不能由当前测试支持的能力声明

命令块前说明目的，命令块后说明预期输出。不要在未运行时使用“运行成功”。

## 分支三：失败与排错记录

围绕诊断链而不是时间流水账组织：

1. 目标和预期成功信号
2. 实际环境与最小复现
3. 首个可观察失败
4. 已排除的原因及证据
5. 当前最可能原因
6. 可行替代路径
7. 仍未验证的部分

保存原始错误信息的必要片段、版本和命令，但移除密钥、账号、内部路径和无关日志。失败本身是有效结果，不把未解决问题包装成教程完成。

## 分支四：领域盘点

先写纳入标准、排除标准、截止日期和“排名/抽样/不完全列表”的性质。为每个对象使用统一字段，推荐包括：

- 团队、工具或公司名称
- 核心方向
- 近年代表工作
- 方法重心与实验接口
- 代码、数据或产品状态
- 当前证据与未核实项

把同类字段整理成表格或卡片。名称、隶属关系、股权、融资、论文状态和人员变动属于时效信息，逐项核对当前一手来源。

## 深解完成条件

- 读者知道从哪里开始，并能判断每一步是否成功。
- 关键 Figure、代码或表格都被解释，而不是仅展示。
- 公开材料无法还原的步骤已经明确列出。
- 文章至少提供一个可执行方法和一个失败判断。
- 篇幅来自教学需要，没有为显得全面而堆积背景。
